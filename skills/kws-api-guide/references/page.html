Common rules

Handle in code

ItemRule
AuthAuthorization: Bearer {token} on every request.
BodySuccess { "code": "OK", "data": ... }, failure { "code": String, "data": null }. Branch on code.
Success200 and 202 are both success with the same data shape.
No codeA proxy 502 or 504 returns a body without code. Treat it as an unknown error.
EnumsAn unknown value must not reject the whole response.

Formats

ItemRule
TypesString? may be null. A field without ? is always present and not null.
Datesdate is "2026-01-15". date-time is UTC.
HeadersRetry-After comes only with 429 EXPORT_4291.

GET/api/v1/exportschanged

The exports screen. Call it when the screen opens and while polling.

Request
queryTypeNotes
limitint?1 to 50, default 20
Response

data: List<Export>, newest first.

FieldTypeNotes
exportIdStringDo not assume a format
statusExportStatusQUEUED, RUNNING, DONE, FAILED
fileUrlString?Only when DONE
Example
{ "code": "OK", "data": [
  { "exportId": "ex_01", "status": "DONE", "fileUrl": "https://files.example/ex_01.csv" },
  ... ] }
Errors
HTTPcodeWhenClient
400EXPORT_4000limit outside 1 to 50Client bug; drop the parameter
503EXPORT_5030The list could not be readShow a retry button
Handling
  1. Draw each row from status.
  2. Poll while any row is QUEUED or RUNNING.
POST/api/v1/exportsnew

The start button. The server queues the export and returns at once.

Request

No body.

Response

202 data: Export with status: QUEUED.

Errors
HTTPcodeWhenClient
429EXPORT_4291Three exports already runningWait Retry-After seconds, then try once
Handling
  1. Add the returned row to the list, then follow it by polling.
