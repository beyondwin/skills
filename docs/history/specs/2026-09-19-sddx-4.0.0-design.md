# sddx 4.0.0 오버레이 수술 설계 스펙

상태: 구현 전 설계. 이 문서는 현재 제품 계약을 변경하지 않는다.

기준: sddx `3.0.0`, Superpowers `6.4.1`, 저장소 `main`, 2026-09-19.
근거: 승인된 브레인스토밍(발화=`/sddx`·`$sddx`만, 범위=호출 잠금+진단된 고비용 결함,
접근=오버레이 수술)과 로컬 계약·Superpowers 드리프트·유사 시스템·논문 조사.
실행 문서: [구현 계획](../plans/2026-09-19-sddx-4.0.0.md).

## 1. 목표와 선택

sddx는 Superpowers SDD 오버레이다. 3.0.0은 워커 실행은 잠갔지만, 발화는
description과 Codex 암시 정책이 HARD-GATE보다 넓고, Superpowers 6.4.1
`task-brief`와 제품 `extract_task.py`가 동시에 지시되며, SDD의 태스크 묶음·중첩
native 컨트롤러를 덮어쓰지 않는다.

이번 개정은 새 오케스트레이션 엔진을 만들지 않는다. **발화를 슬래시/달러로
잠그고, 과제는 `extract_task.py`만 쓰며, SDD 루프에서 런을 깨는 세 규칙을
한 줄씩 덮고, 컨트롤러가 매 과제마다 러너 스키마를 다시 읽지 않게 한다.
오케스트레이션은 호출 세션의 모델·effort를 쓰고, 구현 CLI는 시작 때 한 번
고르며, 구현 effort는 과제 난이도로 High 또는 XHigh다.**

| 대안 | 판단 |
| --- | --- |
| 호출만 잠근다 | 이중 extractor와 태스크 묶음이 남는다. 런을 깨는 쪽을 미룬다. 제외한다. |
| Magentic stall 필드, spawn_subagent 도구 제거, 4조합 라이브 | 작은 이득에 면이 는다. 제외한다. |
| 오버레이 수술 | 발화·추출·루프 오버라이드·dispatch 앞부분만. 채택한다. |

## 2. Global Constraints

- 수정 대상은 `skills/sddx/`, `tests/products/sddx/`,
  `docs/maintainers/products/sddx/`, `scripts/lib/product_contract.py`,
  `tests/repository/test_repository.py`,
  `tests/repository/test_release_contract.py`이다. 다른 제품 설치 파일의
  암시 발화 정책은 바꾸지 않는다.
- Superpowers 파일을 고치지 않는다. SDD 본문을 이 스킬에 복사하지 않는다.
- `run_worker.py`, `resolve_backend.py`, `prepare_grok_sandbox.py`의 플래그,
  argv, `run.json` 스키마, 타임아웃, status 한도는 바꾸지 않는다.
- Python 3.11 이상, 표준 라이브러리만 쓴다. 새 런타임 의존성은 없다.
- 지원 호스트는 `claude-code`, `codex`이다. 워커는 Cursor와 Grok이다.
  호스트를 넓히지 않는다. 지원 OS는 macOS만이다.
- 워커 argv를 바꾸지 않으므로 Cursor/Grok 라이브와 4조합 재측정은 하지 않는다.
- 사용자 문서·모델 응답 원문·자격 증명·공급자 receipt는 픽스처에 넣지 않는다.
- 제품 버전은 `4.0.0`, 날짜는 `2026-09-19`이다. 태그와 GitHub Release는 만들지
  않는다.
- 모든 테스트 명령은 저장소 루트에서 `PYTHONDONTWRITEBYTECODE=1`을 붙인다.

## 3. 구조

sddx는 설치된 Superpowers 6.4.1 SDD를 따른다. 워크트리, ledger,
`sdd-workspace`, `review-package`(빈·비하강 범위 exit 3 포함), 리뷰 프롬프트,
fix loop(1–3 재개, 4–5 fresh XHigh, 5회 breaker), finishing은 상속한다.

이번에 손대는 소유권은 다섯 곳이다.

| 소유 | 4.0.0 규칙 |
| --- | --- |
| 발화 | 사용자 메시지에 `/sddx` 또는 `$sddx`가 있을 때만 켠다. |
| 과제 추출 | Superpowers `task-brief`·`task-start`를 호출하지 않는다. `extract_task.py`만 쓴다. |
| 루프 오버라이드 | 한 워커가 여러 계획 과제를 묶지 않는다. 중첩 native SDD로 내려가지 않는다. 계획에 없는 일은 보내기 전에 한 번 묻는다. |
| 세션과 구현 effort | 오케스트레이션은 이 세션의 모델·effort. 구현 CLI는 시작 때 한 번. 구현 High/XHigh는 과제마다. |
| 컨트롤러 절차 | `dispatch.md` 앞에 짧은 순서를 두고, `run.json`/시그널/status 한도는 뒤로 보낸다. |

Superpowers는 워크스페이스와 리포트 파일 이름을 소유한다. sddx는 구간 추출을
소유한다. 계약의 “SDD가 task-brief를 소유한다”는 문장은 이 구분으로 바꾼다.

## 4. 발화 게이트 — R1

description, HARD-GATE, Codex `openai.yaml`, 저장소 제품 계약이 같은 경계를
말한다.

**description** (frontmatter, `Use when`으로 시작):

```text
Use when the user runs /sddx or $sddx. Do not use for writing a spec or plan, writing-plans, executing-plans including Native inline execution, pre-sdd-review, native subagent-driven-development, or any request that does not contain /sddx or $sddx.
```

“stay orchestrator”, “Grok as implementer”, “external Cursor or Grok CLI
implementer”를 트리거로 쓰지 않는다. 기존 금지 조각(`fresh implementer`,
`fix loop`, `whole-branch`)은 description에 넣지 않는다.

**HARD-GATE**에서 “명시적 외부 implementer 요청” 예외를 삭제한다. 활성화 조건은
사용자 메시지에 `/sddx` 또는 `$sddx`가 있는 것뿐이다. native SDD,
executing-plans(Native inline 포함), writing-plans, pre-sdd-review, 슬래시/달러
없는 외부 구현 요청은 켜지 않는다.

**Codex** `skills/sddx/agents/openai.yaml`은
`allow_implicit_invocation: false`이다. `$sddx`는 명시 호출이므로 그대로
동작한다. `default_prompt`는 `$sddx`를 포함하면 충분하다.

**저장소 계약** `scripts/lib/product_contract.py` `_validate_openai_yaml`:

- `skill_name == "sddx"`이면 `allow_implicit_invocation` 값이 `false`여야 하고
  파일에 `allow_implicit_invocation: true`가 있으면 오류다.
- 그 외 제품은 지금처럼 `true`가 있어야 하고 `false`가 있으면 오류다.

`tests/repository/test_repository.py` `OpenAIMetadataTests`는 제품별로 위 값을
검사한다. how-it-works 등 다른 제품 픽스처는 `true`를 유지한다.

`cases.json`의 `expect` 태그를 실제로 읽는다. 각 태그는 SKILL.md description
또는 본문, 필요하면 `dispatch.md`의 필수/금지 문구 집합에 대응한다. id 목록만
맞추고 태그를 무시하는 검사는 부족하다.

발화 사례: `/sddx …`, `$sddx …` → `activate`.

비발화 사례(기존 유지 + 추가):

| id | request 요지 | expect |
| --- | --- | --- |
| `near-miss-native-sdd` | native subagent-driven-development | `do_not_activate` |
| `near-miss-pre-sdd-review` | `$pre-sdd-review` | `do_not_activate` |
| `near-miss-executing-plans` | executing-plans / Native inline | `do_not_activate` |
| `near-miss-writing-plans` | writing-plans | `do_not_activate` |
| `near-miss-stay-orchestrator` | 오케스트레이터로 남아 있어 | `do_not_activate` |
| `near-miss-grok-implementer-without-slash` | Grok으로 구현 | `do_not_activate` |
| `near-miss-named-sddx-without-slash` | 슬래시/달러 없는 `sddx로 해줘` | `do_not_activate` |

문구 포함만으로 발화를 통과시키지 않는다. description이 비발화 request의
트리거 문구를 포함하지 않는지가 검사다.

## 5. 과제 추출과 브리프 — R2

컨트롤러는 Superpowers `task-brief`와 `task-start`를 호출하지 않는다. 과제
본문은 `extract_task.py`만 쓴다. `--heading`은 `#`을 뺀 제목 전체 일치다.
`Task 1`과 `Task P1:`을 숫자로 추측하지 않는다. 이미 있는 출력 파일은 덮어쓰지
않는다. 플래그 없는 호출의 바이트·exit는 3.0.0과 같다.

출력 경로는 Superpowers `bash scripts/sdd-workspace PLAN_FILE`이 인쇄한 그
계획 디렉터리 아래, 호출마다 새 파일이다. `sdd-workspace`를 Python으로 다시
만들지 않는다. 시도 디렉터리도 가능하면 그 계획 디렉터리 아래에 둔다.

`extract_task.py`에 `--global-constraints`를 추가한다. dispatch는 이 플래그를
**필수**로 적는다.

함수 서명:

```python
def extract_task(
    plan: bytes,
    heading: str,
    *,
    global_constraints: bool = False,
) -> bytes: ...
```

`global_constraints=False`이면 지금과 같이 과제 구간만 돌려준다.

`True`이면 계획에서 ATX 제목(펜스 밖, closing `#` 제거 후)이 정확히
`Global Constraints` 또는 `Global constraints`인 절을 **하나** 고른다. 두
철자는 같은 종류의 절로 센다. 없거나 둘 이상이면 `ValueError`, CLI exit 3.
본문이 공백뿐이면 지금 과제 구간과 같은 빈 본문 오류(exit 3). 절 경계는 기존과
같다: 다음 같거나 더 얕은 제목 앞에서 끝난다. 붙이는 순서는 제약 절 바이트 +
과제 절 바이트다. 사이에 새 개행을 넣지 않는다. 원문 바이트를 그대로 쓴다.

계획이 제약 절이 없으면 컨트롤러는 제약을 지어내지 않고 extract 실패를
ledger에 남긴 뒤 워커를 보내지 않는다.

`Search paths`, `Worker checks`, `Host checks`와 과제 결정은 지금처럼
컨트롤러가 추출 결과 위에 적는다. 브리프 전체를 스크립트가 쓰지 않는다.

## 6. 루프 오버라이드 — R3

이름 있는 계획 과제 사이에는 Superpowers처럼 매 과제마다 사용자에게 묻지
않는다. 아래 세 규칙은 SDD 6.4.1보다 우선한다. SDD 본문은 복사하지 않는다.

1. **한 워커, 한 과제.** 계획의 과제 제목 하나가 워커 하나, 리뷰 패키지 구간
   하나다. 같은 모양의 한 줄 수정이어도 묶지 않는다.
2. **중첩 native SDD 금지.** 지금 세션이 컨트롤러다. 한 단계 아래 서브에이전트에
   `subagent-driven-development`를 통째로 맡기지 않는다. 중첩 sddx 컨트롤러
   기계는 만들지 않는다.
3. **계획에 없는 일.** 계획이 이름 붙이지 않은 일(계획에 없는 수정, 하니스
   수리, 측정 재실행)은 보내기 전에 한 번 묻는다. “끝까지 돌려”는 계획에 있는
   과제만 덮는다. 설계 모호함은 XHigh가 아니라 ruling이다.

cases에 `no-task-brief`, `no-batch-same-shape`, `no-nested-native-sdd`,
`unplanned-work-ask-once`를 두고 expect 문구를 SKILL.md에서 검사한다.

## 7. 세션 오케스트레이션과 과제별 구현 effort — R5

3.0.0은 리뷰어 모델을 오케스트레이터에 묶고, 구현 effort는 동시성·race·얽힌
부작용이 있을 때만 XHigh로 올린다. 세션이 XHigh여도 구현이 High에 머물거나,
반대로 세션 effort를 구현에 그대로 복사하는 식으로 읽힐 수 있다. 픽커 선택지
이름도 “Cursor Agent CLI (Grok model)” / “Grok Build CLI”라 시작 질문이
모델 선택처럼 들린다.

**오케스트레이터.** `/sddx` 또는 `$sddx`를 받은 그 세션이 오케스트레이터다.
모델과 effort는 그 세션의 값이다. 더 싼 모델, 최종 최상위 모델, 구현 워커와
같은 모델 계열로 바꾸지 않는다. 시작 때 current-state에 한 줄로 기록한다:

```text
Orchestrator: <claude-code|codex>; model: <id or inherited-unknown>; effort: <session>
```

확인할 수 없으면 `inherited-unknown`이고 추측하지 않는다. 리뷰어도 이 모델을
따른다. 리뷰 **effort**는 기존 위험 트리거(잠금·권한·sandbox, round 4–5,
반복 누락)를 유지한다. 세션이 이미 XHigh 이상이면 리뷰 승급 정의는 쓰지 않고
세션을 낮추지도 않는다.

**구현 CLI는 시작 때 한 번.** argv에 `cursor|grok|c|g`가 없으면 이 계획에서
한 번 묻는다. 선택지 문구:

- Grok CLI — Grok이 모델을 고른다. `--model`을 넘기지 않는다. 요청 effort는
  `--reasoning-effort` 또는 `--effort`로만 전달한다.
- Cursor Agent (Grok) — 이 과제의 요청 effort와 마지막 세그먼트가 같은
  확인된 Grok 모델 id. 버전은 기존처럼 숫자 비교로 가장 높은 것을 고른다.

Grok CLI에 `grok-4.6`을 argv로 고정하지 않는다. 3.0.0 계약이 Grok의 `--model`을
거절한다. 워커가 보고한 모델 id는 ledger에 적고, 적용 여부를 측정하지는 않는다.
Cursor 목록에 요청 effort의 Grok id가 없으면 다른 effort로 바꾸지 않고 그
사실을 보고한다. 세 번째 구현기, Claude 구현기, 과제마다 CLI를 다시 묻는
일은 없다.

**구현 effort는 과제마다.** 컨트롤러가 브리프와 소유 파일만 보고 고른다.
사용자에게 과제마다 묻지 않는다. 세션 effort를 복사하지 않는다. 리뷰어 XHigh가
구현 XHigh를 강제하지 않고, 그 반대도 아니다.

| 구현 | Effort |
| --- | --- |
| 요구가 분명하고 로컬·기계적인 변경, 단순한 통합 | High (기본) |
| 동시성·race·잠금·순서·공유 상태, auth·권한·secret·sandbox 경계, 여러 하위계가 얽힌 부작용, 이 과제에서 High 리뷰가 이미 실패한 경우 | XHigh |

설계 모호함은 XHigh가 아니라 ruling이다. 파일 수, 줄 수, “중요해서”, “안전하게”
는 트리거가 아니다.

ledger: `Task N worker-effort: high|xhigh — <reason>`. current-state:
`Worker effort: high|xhigh — <reason>`. 이유를 대지 못하면 High다.

**재개와 effort 상승.** fix 1–3은 **같은 요청 effort**일 때만 같은 세션을
재개한다. High가 실패한 뒤 XHigh로 올리면 새 워커다. Cursor는 effort가 모델
id에 들어 있어 High 세션을 재개하면 XHigh가 적용되지 않는다. round 4–5는
기존처럼 fresh XHigh다.

## 8. 컨트롤러 절차와 `dispatch.md` — R4

`dispatch.md` 앞부분은 컨트롤러 순서만 남긴다. `run.json` 필드, 시그널,
status 바이트 한도는 `## Runner already does this` 아래로 옮기고 의미를 바꾸지
않는다. 새 실행 스크립트는 만들지 않는다.

앞부분 순서:

1. `python3 "<skill-root>/scripts/resolve_backend.py" --backend <id> --json`.
   `available: false`면 멈추고 `reason`만 보고한다. 다른 backend로 바꾸지 않는다.
2. Superpowers `bash scripts/sdd-workspace PLAN_FILE`로 이 계획 디렉터리를 받는다.
3. `python3 "<skill-root>/scripts/extract_task.py" <plan-file> --heading "<제목>" --global-constraints --output <새 경로>`.
   그 위에 Search paths / Worker checks / Host checks와 과제 결정을 적는다.
   `task-brief`와 `task-start`는 호출하지 않는다.
4. Grok이면 `prepare` → `run_worker.py run` → 호스트 잡으로 기다림 → 필요한
   `status` 창만 → 워커와 그 자식 종료 확인 → `cleanup`. Cursor면
   prepare/cleanup 없이 같은 run/status다.
5. 프로세스 exit 0은 DONE이 아니다. 보고서, 실제 테스트 exit, 커밋, tools
   인덱스, 네이티브 리뷰로 판정한다. 로그 전체를 이 세션에 붙이지 않는다.

`SKILL.md` Controller 절은 이 순서를 가리키고, 상속 목록에서 `task-brief`를
뺀다. 스키마 문장은 `dispatch.md` 뒤에만 둔다.

402 후 재시도 금지, 호스트 검사만 남은 경우 워커를 다시 안 부르는 규칙, 같은
status 오프셋 짧은 폴링 금지는 그대로다.

## 9. 테스트와 문서

필수 증거: `python3 scripts/verify.py --skill sddx`. 머지 전
`python3 scripts/verify.py`.

잠글 검사:

- description이 `/sddx`·`$sddx`만 켜고 R1의 비발화 문구를 트리거로 갖지 않는다.
- HARD-GATE에 “explicit external implementer request”가 없다.
- `openai.yaml`은 sddx만 `false`, 다른 등록 제품은 `true`.
- `cases.json` expect 태그가 문서 문구 집합에 대응한다.
- `extract_task.py --global-constraints`: 절이 있으면 과제 앞에 붙고, 없거나
  둘이면 exit 3, 기존 파일은 덮지 않는다. 플래그 없는 호출은 기존 테스트가
  그대로 통과한다.
- SKILL.md와 dispatch.md가 `task-brief`를 호출하지 말라고 하고,
  `--global-constraints`를 필수로 적는다. 묶음 파견·중첩 native SDD를 금지한다.
- 오케스트레이터는 이 세션의 모델·effort다. 픽커 선택지는 Grok CLI / Cursor
  Agent (Grok) 두 개다. 구현 effort는 과제마다 High 또는 XHigh이고 세션
  effort를 복사하지 않는다. effort가 오르면 새 워커다.

관리자 문서:

- `contract.md` 하드 게이트, 추출 소유권, `--global-constraints`, 루프
  오버라이드, 세션 오케스트레이션, 과제별 구현 effort, 함께 고칠 파일.
- `references/current-state.md`에 `Orchestrator`와 `Worker effort` 필드.
- `release.md`의 낡은 `2.0.0` 개발 목표·Unreleased 지칭을 `4.0.0`에 맞춘다.
- `compatibility.md`는 워커 측정 표를 다시 돌리지 않는다. 표가 2.0.0대 CLI
  측정이며 4.0.0에서 워커 argv를 바꾸지 않았다는 한 줄을 추가한다. 발화·추출
  변경은 그 표의 단위가 아니다.
- `testing.md`에 4.0.0 오프라인 검사 절을 추가한다. 라이브 워커 재실행은
  요구하지 않는다.
- README 두 벌의 When to use는 `/sddx`·`$sddx`만 켠다고 적는다.

## 10. 하지 않는 것

- SDD 본문 복사, Superpowers 파일 수정, 새 오케스트레이션 엔진.
- Beads, tmux, Magentic 팀, stall 필드, 새 상태 파일.
- `spawn_subagent` 도구 제거 재시도, Cursor positional prompt / `--resume` 값
  여부 재설계, 적용 effort 측정.
- worker-prompt 두께 늘리기. 1.0.2 이후 검색 경계를 다시 쓰지 않는다.
- Windows, 호스트 확대, 카탈로그 편입.
- `sddx-reviewer-xhigh` 라이브 로딩. 공개 태그 전 기존 release 절차로 남긴다.
- Cursor/Grok 라이브와 4조합 재측정.
- `extract_task.py`에 Task-번호 매칭을 넣거나 Superpowers `task-brief`를
  제품에 복사하는 일.
- Grok CLI에 `--model grok-4.6`을 넣거나, Cursor에서 Grok이 아닌 모델을
  고르거나, 구현 CLI를 세 개로 늘리는 일.
- 과제마다 구현 effort를 사용자에게 묻는 일. 적용된 모델 effort를 측정하는
  경로를 새로 만드는 일.
