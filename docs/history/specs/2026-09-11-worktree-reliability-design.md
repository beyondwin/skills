# SDDx worktree 실행 개선 설계

날짜: 2026-09-11

상태: 2026-09-11 사용자 문서 승인. 제품 구현은 시작하지 않음.

## 목적과 근거

외부 worker가 구현·테스트·커밋까지 수행하는 기존 SDDx 흐름을 유지하면서,
linked worktree에서 확인한 커밋 실패와 역할 이탈을 줄인다.

2026-09-11 Codex / Grok CLI 1.0.25 검증에서 다음을 관측했다.

- `--sandbox workspace`가 worktree 밖 Git index 쓰기를 막아 `git add`가 실패했다.
- 프로세스는 exit 0이었지만 worker의 작업 상태는 `BLOCKED`였다.
- 첫 worker는 금지된 Superpowers 스킬과 전체 계획을 읽었다.
- 역할을 재명시한 후속 호출에서는 같은 스킬 읽기가 관측되지 않았다.
- 컨트롤러가 커밋만 보조한 실행에서 두 작업의 최종 테스트 6개와 코드 리뷰가 통과했다.

이 기록은 원본 SDDx의 정상 완료 증거가 아니다. 기존 원시 로그와 테스트 저장소는
로컬에 보존하며, 이 설계에 공급자 receipt나 호스트 개인 경로를 복사하지 않는다.

Grok [sandbox 문서](https://docs.x.ai/build/features/sandbox)와
[설정 문서](https://docs.x.ai/build/settings/reference)는 `workspace`를 상속하는
사용자 정의 프로파일과 추가 쓰기 경로 `read_write`를 설명한다.
설치된 1.0.25에서 이 설정으로 worker 커밋까지 되는지는 아직 확인하지 않았다.

## 유지할 사용자 흐름

사용자는 기존대로 `sddx <plan-file> [cursor|grok]`를 호출한다.
추가 사용자 옵션이나 작업마다 새로운 선택 화면을 만들지 않는다.

Superpowers가 worktree, ledger, task brief, 리뷰와 수정 반복을 계속 소유한다.
외부 worker는 구현·테스트·커밋·보고를 담당하고 리뷰어는 호스트 네이티브다.
컨트롤러가 대신 커밋하는 경로를 정상 실행으로 추가하지 않는다.

## 변경 1: 작은 Grok sandbox 보조 도구 하나

`skills/sddx/scripts/prepare_grok_sandbox.py` 하나에 준비와 정리를 모은다.
모델을 호출하거나 worker 프로세스를 관리하지 않는다.
기존 `resolve_backend.py`는 CLI 발견과 플래그 확인을 하는 읽기 전용 도구로 유지한다.

준비 동작은 다음으로 제한한다.

1. 전달받은 worktree에서 Git 명령으로 실제 Git 디렉터리와 공용 Git 디렉터리를 구한다.
   `.git`이 디렉터리일 것이라고 추측하거나 경로 구조를 하드코딩하지 않는다.
2. `workspace`를 상속하는 `sddx-worktree` 프로파일에 필요한 Git 디렉터리를
   `read_write`로 넣는다. 중복 경로와 이미 worktree 안에 있는 경로는 제외한다.
3. worktree의 `.grok/sandbox.toml`에 해당 프로파일만 추가한다.
   기존 설정과 주석을 보존한다. 같은 이름의 프로파일은 `extends`와 `read_write`가
   예상값과 일치하고 다른 필드가 없을 때만 재사용한다.
   같은 이름의 다른 설정, 잘못된 TOML, 심볼릭 링크 대상은 덮어쓰지 않고 원인을 반환한다.
4. 준비 결과의 프로파일 이름으로 기존 argv의 `--sandbox workspace`를 교체한다.
   worker의 cwd는 계속 같은 Superpowers worktree다.

이 설정은 공용 Git 디렉터리에도 쓰기를 허용하므로 브랜치별 권한 격리는 아니다.
현재 작업 브랜치만 수정한다는 worker 규칙과 변경 범위 검토를 계속 적용한다.
Git 내부 파일마다 별도의 허용 규칙을 만드는 복잡한 권한 체계는 도입하지 않는다.

추가한 설정은 작업 커밋에서 제외한다. 기존 SDD evidence 디렉터리에 정리에 필요한
원래 내용과 추가 결과만 기록하고, worker가 끝난 뒤 직접 추가한 내용만 정리한다.
파일에 다른 변경이 생겼으면 자동으로 이전 내용으로 덮어쓰지 않고 남은 차이를 알린다.
전역 Grok 설정과 기존 사용자 파일은 임의로 교체하지 않는다.

사용할 필수 플래그가 없거나 프로파일 준비가 실패하면 구현 전에 `BLOCKED`로 알린다.
커밋 권한 오류가 계속되면 같은 호출을 반복하지 않고 해당 오류를 보고한다.

## 변경 2: 짧고 완결된 worker 지시

`worker-prompt.md`를 작업 brief 우선, 구현·테스트·커밋·보고의 순서로 명확히 한다.
brief에는 필요한 요구사항과 검증 명령을 포함한다. 저장소의 적용 가능한 작업 지침과
구현에 필요한 소스는 읽되, 전체 계획을 다시 탐색하거나 외부 스킬을 호출하지 않는다.
설계가 빠져 있으면 추측 대신 기존 `NEEDS_CONTEXT`를 사용한다.

Grok에는 확인된 `--rules`로 이 역할을 전달하고 기존 `--no-plan`, `--no-subagents`,
`--disable-web-search`를 유지한다. 추가 reviewer나 MCP 도구를 worker에서 호출하지 않는다.
이 역할 규칙은 프롬프트 지침이며 파일 접근을 강제하는 보안 경계로 설명하지 않는다.

사용자 스킬·플러그인·인증 환경 전체를 복제하거나 재구성하는 기능은 만들지 않는다.
MCP 도구 호출과 서버 초기화 경고도 구분한다. 실제 검증에서 역할 이탈이 반복되면
완료로 판정하지 않고 관측된 원인에 필요한 설정만 후속 검토한다.

## 변경 3: 기존 보고서로 완료 확인

새 상태 체계나 보고서 파서를 만들지 않는다. 컨트롤러가 기존 report, Git, 테스트,
Superpowers 리뷰 절차를 함께 확인한다.

- exit 0은 프로세스 종료 결과일 뿐 작업 완료 조건이 아니다.
- `BLOCKED`, `NEEDS_CONTEXT`, 보고서 누락, 불명확한 결과는 완료로 처리하지 않는다.
- `DONE`도 검증 명령의 실제 종료 결과와 작업 변경의 커밋 여부를 확인한다.
  변경 없는 재검증에는 의미 없는 새 커밋을 요구하지 않는다.
- `DONE_WITH_CONCERNS`는 우려를 읽고 기존 ruling 절차로 처리한다.
- 네이티브 리뷰까지 통과해야 해당 task를 완료로 기록한다.

세션 재개와 High/XHigh 전환은 기존 SDDx 규칙을 유지한다.
그 규칙을 실행하는 별도 오케스트레이터나 자동 재시도 계층은 만들지 않는다.

## 검증과 완료 기준

공급자 없는 회귀 검증은 실제 임시 Git 저장소와 linked worktree를 사용한다.
Git 경로 계산, 프로파일 준비·정리, 기존 설정 보존, 이름 충돌, 공백이 있는 경로와
이미 worktree 안에 Git 디렉터리가 있는 경우를 확인한다.
가짜 CLI 검사에서는 실제로 사용할 필수 플래그 누락을 검출한다.
이 테스트들을 sandbox 안에서 커밋이 된다는 증거로 확대하지 않는다.

worker 지침과 완료 규칙은 `exit 0 + BLOCKED`, 보고서 누락, 스킬 재호출 유도 상황으로
행동 검증한다. 문서에 금지 문구가 있다는 검사만으로 준수됐다고 판단하지 않는다.

제품 변경 후 `python3 scripts/verify.py --skill sddx`와 필수 전체 검증
`python3 scripts/verify.py`를 실행한다. 승인된 라이브 검증에서는 새 throwaway fixture로
다음을 확인하며, 이 문서 작성 단계에서는 모델을 호출하지 않는다.

- 같은 linked worktree에서 worker가 두 작업을 직접 구현·테스트·커밋한다.
- 검증용 리뷰 지적을 같은 worker 세션으로 전달하고 수정 및 재검토를 확인한다.
  검증용 지적과 실제 코드 리뷰에서 발견한 결함은 기록에서 구분한다.
- 컨트롤러의 커밋 보조 없이 최종 테스트와 네이티브 리뷰가 통과한다.
- 생성 설정이 task 커밋에 들어가지 않고 실행 전 사용자 설정이 보존된다.

Cursor와 Claude Code를 실제 실행하지 않았다면 해당 조합은 미검증으로 남긴다.

## 변경 범위

SDDx의 SKILL, dispatch, worker prompt, resolver의 필수 플래그 검사,
sandbox 보조 도구, 제품 계약·README·테스트·호환성 기록을 함께 갱신한다.
설치 파일 변경에 따른 제품 버전과 CHANGELOG도 맞춘다.

Superpowers 파일, 다른 제품, frozen catalog, 지원 호스트 목록은 변경하지 않는다.
일반 실행 프레임워크, 별도 상태 저장소, 컨트롤러 커밋 모드와 공급자 자동 전환은 범위 밖이다.
