# 한국어 기술 글쓰기 실험을 개인용 도구로 어떻게 이어갈까?

결정일: 2026-10-09. 기록일: 2026-10-09.
관련 작업: 개인용 `readable`(Readable, 이전 `ko-technical-writing`), 한국어 글쓰기 정책 후속 실험.
결과: 개인용 Readable 0.6.0으로 이름 변경. 아래 실제 모델 검증은 이전 이름의 0.5.1 결과. 최종 합성 과제 작성 8개·다른 제공자 검토 8개·기존 기능 검사 3개·설치 후 검사 1개 통과. 개인용 절대 기준으로 채택했으며 비교 실험의 우월성 기준은 미달. 사람 이해도 향상은 미측정.
근거 성격: 사용자의 개인용 제품화 요청, 기존 연구, 이번 후속 실행.

## 시작한 문제

사용자는 한국어 기술 글쓰기·ASD-STE100 응용 전달 자료와 실제 모델 실험을
바탕으로 자신이 쓸 제품을 만들기를 요청했습니다. 코드 리뷰 제품으로 이해했던
에이전트의 앞선 제안은 잘못된 범위였으며, 한국어 기술 글쓰기로 바로잡았습니다.
사용자는 만족할 품질까지 진행하도록 요청했고 슈퍼파워스 사용을 금지했습니다.

## 당시 조건

[기존 연구](../../research/2026-10-ko-clear-writing-eval/README.ko.md)는
긴 지침의 일반적인 우위를 입증하지 않았습니다. 짧은 지침에서도 범위를 벗어난
커밋 설명이 나왔고, 미제공 근거를 미실행으로 단정하는 오류가 관측됐습니다.
기존 실험은 지침 전체를 입력에 넣었으며 실제 파일 읽기와 자동 선택을 측정하지
않았습니다. 이를 이번에 확인할 핵심 질문으로 삼습니다.

## 대안과 선택

전역 지침 추가, 개인용 작업 스킬, 기존 교정기 확장, 필수 검사 도구를 비교했습니다.
이번에는 근거 기반 초안 작성에 한정한 짧은 개인용 스킬을 선택했습니다.
이미 있는 공통 지침을 반복하거나 교정기의 역할을 넓히지 않습니다. 알려진 결함이
있는 원본 검사기는 필수 도구로 채택하지 않습니다. 원본 비공개 자료는 복제하지 않고
측정된 문제를 해결하는 지침을 새로 작성합니다.

저장소의 세 제품 목록은 유지합니다. 연구 폴더에 평가 후보와 재현 자료를 보존하고,
검증된 후보를 사용자의 개인 스킬 경로에 설치하는 범위입니다. 새 저장소 지원 제품,
다른 호스트 지원, 다른 프로젝트의 공통 지침 배포를 뜻하지 않습니다.

## 구현 방법

짧은 진입 지침과 커밋·PR 및 문서·인계용 참조 두 개를 둡니다. 새로운 모델 호출 없이
현재 모델이 자료를 읽고 작성합니다. 평가에서는 격리된 새 Codex 세션, 합성 저장소,
일반 실행과 후보 비교, 의미 기준과 실제 읽기 기록을 사용합니다. 후속 호출 상한은
24회이며 실패도 횟수에 포함합니다. 원본 실행 로그는 Git 밖에 보관합니다.

## 확인한 결과

[후속 연구](../../research/2026-10-personal-writing-pilot/README.ko.md)에
과제·사전 기준·판정·모델 실행 정보·비용 대용 지표·설치 해시를 보존했습니다.
21회 시도 중 서버 용량 부족 1건을 제외한 20개 답변을 평가했습니다. 같은 일상 대화
과제를 한 번 재시도한 사실도 숨기지 않았습니다.

후보와 일반 실행 모두 새 작성 과제 8/8을 통과했습니다. 후보는 8개 모두 실제 지침과
참조를 읽었고, 제외 대상 4개에는 개입하지 않았습니다. JSON의 값과 키를 보존했고
모든 실행의 파일·인덱스·HEAD가 유지됐습니다. 의미 판정은 작성자가 수행했으며
독립 채점이나 사람 이해도 실험은 아닙니다.

일반 실행도 동일하게 잘했고, 스킬은 토큰을 더 사용하며 답변이 길어졌습니다.
효과가 입증됐다는 이유로 채택한 것이 아닙니다. 사용자가 요청한 개인용 작업 흐름을
반복 가능한 형태로 갖추고, 관측한 인수 범위를 통과했다는 이유로 시험판을 설치했습니다.
이는 관측 결과와 별개인 제품 선택입니다.

## 유지와 종료 판단

동결한 후보를 수정 없이 개인 스킬 경로에 복사했고 6개 파일의 해시 일치를 확인했습니다.
전역 AGENTS, 기존 제품, 지원 호스트, 다른 프로젝트 설정은 변경하지 않았습니다.
일반 실행과 동률인 결과를 바꾸기 위해 추가 실험을 반복하지 않았습니다.
새 대화에서 사용자가 선택할 수 있는 시험판으로 마무리합니다.

실제 파일 저장, 모든 개인 플러그인과의 공존, 다른 호스트, 사람 이해도와 장기간
효용은 남은 한계입니다. 부담이 크면 절차와 지침을 더 줄이거나 제거하는 쪽으로
판단할 수 있으며 이번 단회 실험을 일반적인 성능 보증으로 쓰지 않습니다.

## 다음에 쓸 배움

현재의 해석: 지침 자체의 의미 검토와 실제 자동 선택·자료 읽기를 나눠 확인해야 합니다.
또한 CLI 요약 이벤트가 도구 실행 전체를 담는다고 가정하면 실패한 복합 명령에서
확보한 유효한 근거까지 놓칠 수 있습니다. 이번에는 전체 rollout을 대조해 이를
바로잡았고 집계에서 두 종류의 개수를 구분했습니다.

## 후속 결정: 의미 보존을 넘어 읽기 품질을 다루기

사용자는 정확한 글을 만드는 것만으로는 목적을 달성하지 못한다고 지적했습니다.
목표는 사람이 원인과 조건, 다음 행동을 한 번에 이해하는 자연스러운 기술 설명입니다.
앞선 8/8은 의미 보존과 실행 경로의 확인이며 읽기 품질의 증거가 아닙니다.

0.1.0의 동결된 후보와 결과는 보존하고 0.2.0 후보를 별도 연구 폴더에 작성합니다.
문장 수 제한이나 금지어 목록 대신 독자 질문 중심 구성, 인과 연결, 구체적 동사,
모호한 지시어와 반복을 고치는 편집을 선택했습니다. 정확성 규칙은 유지합니다.

새 비교에서는 일반 실행·0.1.0·0.2.0으로 복잡한 합성 과제 6개를 작성합니다.
버전을 숨긴 모델 평가를 순서를 바꿔 두 번 실시합니다. 별도로 원문을 보지 못하는
모델이 문서만 읽고 이해 질문에 답하게 합니다. 이는 사람 실험의 대체 증거가 아니라
문서에 필요한 설명이 있고 추출 가능한지를 확인하는 보조 검사입니다.
이번 호출 상한은 실패 포함 40회입니다. 설치 여부와 우위 주장은 실행 전 동결한
[후속 프로토콜](../../research/2026-10-writing-readability/protocol.json)로 판단합니다.

### 다른 모델에서 드러난 결함

사용자는 Claude CLI의 Opus와 Cursor Agent의 Grok도 추가로 검증하도록 요청했습니다.
Codex에서는 대부분의 점수가 상한에 모였습니다. 같은 모델의 높은 평가만으로 품질을
판단하지 않고, 두 제공자의 일반 실행·후보 비교와 서로 다른 제공자의 평가를 추가합니다.
이 실험은 스킬을 입력에 넣으므로 Claude/Cursor 자동 선택 지원의 증거는 아닙니다.

Opus 후보는 p95 증가를 가장 느린 5% 구간이 느려졌다고 일반화했습니다.
평균과 백분위 같은 집계값만으로 개별 요청 전체의 변화를 알 수 없습니다.
Grok 후보의 복구 절차는 실행 단계에서 앞부분의 조건표를 다시 보게 했습니다.
이는 사용자가 요청한 첫 읽기의 이해와 실행 가능성에 맞지 않습니다.

따라서 0.2.0은 의미·읽기 품질 검증을 통과한 최종판으로 채택하지 않습니다.
기존 자료를 유지하고 0.2.1에서 집계값의 확대 해석, 반복된 상태 설명, 분리된 조건과
행동을 보완합니다. 문체를 무한히 탐색하지 않도록 한 번의 편집으로 마무리합니다.
새 합성 과제 두 개를 세 모델에서 확인하고, 실패한 성능 보고 재현·JSON 회귀·설치 후
실행을 포함해 별도 최대 10회로 검증합니다. 0.2.0 점수를 수정본으로 승계하지 않습니다.

### 숫자 표의 모순 때문에 다시 보완한 이유

0.2.1에서 원래 겨냥한 백분위 해석과 절차의 조건 배치는 나아졌습니다. 그러나 Grok의
새 성능 보고에서 B의 성공 건수를 적을 표 칸에 A의 오류 제외 조건이 들어갔습니다.
본문의 B 성공 1,000건은 맞았지만, 본문이 맞아도 잘못된 표 칸이 고쳐지는 것은 아닙니다.
사전에 정한 의미 보존 조건에 어긋나므로 이 후보도 채택하지 않습니다.

0.2.2는 숫자 표의 각 열을 원자료의 대상·단위·상태와 대조하고, 본문에서 반복한 값과도
일치하는지 확인하도록 보완합니다. 사용자가 요청한 계속 검증 범위에서 별도 최대
10회로 같은 회귀 과제를 다시 실행합니다. 이는 이미 본 결함의 회귀 검사이며 새로운
독립 비교나 사람의 이해도 향상 증거로 제시하지 않습니다.

## 최종 결과와 종료 판단

개인용 설치본을 0.2.2로 갱신하고 여섯 파일의 일치를 확인했습니다. 마지막 회귀 라운드는
10회 시도 중 9개 답변이 완성됐습니다. 세 모델의 두 과제씩, Opus의 기존 성능 보고,
JSON 작성, 설치 후 실제 호출을 대조했습니다. Grok의 첫 복귀 절차는 제한 시간에 걸려
동일 입력으로 한 번 재시도했고, 두 실행을 모두 보존했습니다.

앞부분의 조건표를 다시 찾던 절차와 표·본문의 수치 모순은 표적 과제에서 재현되지
않았습니다. 백분위 경계와 개별 요청의 변화를 구분했습니다. 확인한 결함을 보완하고
개인용 Codex에서 사용할 수 있다는 근거로 이 시점에 마무리합니다. 모든 문장을 완벽하게
만들었다는 뜻이 아닙니다. 특히 Grok은 여전히 느리고 문체도 어색한 부분이 있습니다.

채택은 현재 모델을 쓰는 개인용 Codex 범위입니다. 추가 모델 호출을 제품의 필수 절차로
넣지 않았으며, Claude/Cursor 설치 지원도 선언하지 않았습니다. 이전 후보의 높은 점수는
최종 버전으로 승계하지 않습니다. 사람의 첫 읽기 이해도와 장기적인 사용감은 아직
측정하지 않았으므로 그런 효과가 입증됐다고 보고하지 않습니다.

자세한 실행 수, 오류와 재시도, 비교 및 비용 대용 지표, 남은 한계는
[읽기 품질 연구](../../research/2026-10-writing-readability/README.ko.md)에 모았습니다.


## 후속 결정: 우월성 요청을 검증 가능한 비교로 바꾸기

사용자는 우월성이 확정될 때까지 개선하도록 요청했습니다. 원하는 결론이 나올 때까지
같은 평가를 반복하면 결과를 과장할 수 있으므로, 새 후보와 과제 및 채택 기준을 먼저
고정했습니다. 0.3.0 후보는 독자 질문과 인과 관계에 필요한 정보를 선택하는 데 집중하고,
관측된 반복·조건 분산·문체 문제를 줄이려 합니다. 현재 0.2.2는 채택 판정 전까지 유지합니다.

일반 작성·0.2.2·0.3.0의 새 합성 과제 12개를 세 모델에 배정하고, 다른 제공자가 버전을
가린 채 두 가지 순서로 비교합니다. 두 비교를 모두 통과해야 하며 의미 오류는 채택을
막습니다. 같은 글의 순서별 평가는 표본 수를 늘리지 않습니다. 최대 70회 호출과 판정식은
[후속 설계](../../research/2026-10-writing-superiority/design.md)에 기록했습니다.
사람의 자연스러움·첫 읽기 이해도는 이번 모델 평가로 확정할 수 없습니다.


### 후속 비교 결과와 보정의 한계

새 후보 0.3.0은 일반 작성에 7승·1패·4건 판정보류, 설치본 0.2.2에 3승·0패·9건
판정보류였습니다. 두 순서의 평가가 일치할 때만 승패로 세었습니다. 사전 기준인
각 비교 8승 이상과 단측 확률 0.025 이하를 충족하지 못했고, Grok 평가 한 건은
480초에 종료됐습니다. 결과가 유리해질 때까지 재시도하거나 판정 기준을 바꾸지 않았습니다.

0.3.0의 첫 문장이 예외를 뒤로 미루면서 적용 범위를 넓힌 문제를 고쳐 0.3.1을
만들었습니다. 이 보정에서 인가를 인증으로 번역하고, 효과가 확인되지 않았다는 사실을
효과가 없다는 단정으로 바꾸는 오류가 새로 드러났습니다. 다시 보완한 0.3.2는 세 모델의
표적 설명 검사 여섯 번과 JSON 검사 한 번에서 작성자 대조를 통과했습니다. 이전 비교
점수는 수정본의 우월성 근거가 될 수 없으므로 세 후보 모두 설치하지 않았습니다.

모델 평가 자체에도 오탐이 있었습니다. A·B 비교 표현을 B 자체의 과거 변화로 보거나,
503 재시도의 안전성을 보장하지 않는 경고를 401 재시도 허용으로 해석했습니다. 이런
평가에 맞춰 글을 수정하면 오히려 불필요한 설명과 방어적인 문장이 늘 수 있습니다.
관측된 오탐과 실제 원자료 오류를 구분해 남겼습니다. 단순한 정답·오답 대조군 통과는
모델 평가자의 낮은 오탐률까지 입증하지 않습니다.

전체 78회 호출에서 77개 답변을 받았습니다. 최종 보정은 표적 회귀 근거이며 사람의
자연스러움이나 전체 문서의 우월성을 확정한 결과는 아닙니다. 현재 설치본 0.2.2의
파일 일치를 확인하고 유지했습니다. 이후 사용자는 익명 비교 세 쌍에서 B·B·A를
선택했습니다. 대응표로는 0.2.2 한 번, 일반 작성 두 번이었지만, 곧 모두 구분하기
어려웠고 모든 글의 용어가 사람이 쓰는 말 같지 않았다고 설명했습니다. 따라서 처음의
1 대 2를 뚜렷한 선호로 해석한 판단은 철회합니다. [독자 응답](../../research/2026-10-writing-superiority/human-preferences.json)에
최초 선택과 후속 설명을 함께 남겼습니다. UI 시험용 선택은 집계하지 않습니다.

이번 피드백은 사실 보존과 모델 선호만으로 사용자가 원하는 자연스러움을 검증할 수
없다는 구체적인 근거입니다. 원문에는 `UI 소비 코드`, `nullable이다`, 설명 없는
`dual-write`와 여러 영문 역할명이 있습니다. 이 표현들은 작성자가 찾아낸 개선 후보이며
사용자가 개별적으로 지정한 단어는 아닙니다. 영어 중심 합성 입력을 그대로 옮긴 것이
원인일 수 있지만 원인은 아직 검증하지 않았습니다.

다음에는 용어를 일괄 번역하거나 금지어 규칙을 쌓기보다, 식별자와 기술적 구분을 보존한
채 익숙한 말로 개념을 설명하는지 비교해야 합니다. 현재 기록과 설치본은 보존합니다.
짧은 설명 예시를 만드는 것과 스킬의 효과를 실제로 입증하는 것은 구분하며, 독자의
평가 전에는 개선됐다고 선언하지 않습니다. 이번 세 쌍은 0.2.2와 일반 작성의 비교로,
0.3.2의 평가나 전체 문서에 대한 우열 근거가 아닙니다.

[후속 결과](../../research/2026-10-writing-superiority/README.ko.md)와
[통합 집계](../../research/2026-10-writing-superiority/study-summary.json)에 실패한 후보,
보정, 평가자 문제와 실행 한계를 모두 보존합니다. 사용자가 요청한 우월성 확정은
아직 달성하지 못했습니다. 현재 자료로 정당화할 수 있는 것은 발견한 결함의 보완이며,
우월성 확정에는 최종 후보의 새 비교와 실제 독자 기준이 더 필요합니다.


## 후속 수정: 익숙한 말로 개념을 설명하기

사용자는 사람이 실제로 자주 쓰는 용어로 직관적이고 읽기 좋은 글이 되도록 수정하고,
작성자가 충분하다고 판단할 때까지 검증하도록 요청했습니다. 따라서 이전의 우월성
확정과 구분해 개인용 도구의 실용적인 채택 기준을 새로 정합니다. 독자의 선호나
이해도 향상이 입증됐다고 선언하는 기준은 아닙니다.

0.4.0 후보는 0.3.2의 의미 보존 수정을 바탕으로 낯선 명칭보다 행동과 역할을 먼저
설명하도록 바꿉니다. 모든 영어를 번역하거나 금지어 목록을 만드는 대안은 버렸습니다.
서버·배포처럼 익숙한 말은 유지하고, 식별자와 기술적 구분은 필요한 곳에서 정확히
씁니다. 단어의 실제 사용 빈도를 측정한 것은 아니며 작성자의 언어 판단입니다.

기존 독자 비교에 나온 세 과제와 새 합성 과제 세 개를 현재 설치본과 비교합니다.
새 과제는 한국어 원자료로 만들어 영어 입력에만 맞춘 검사가 되지 않도록 했습니다.
[설계와 실행 전 기준](../../research/2026-10-writing-plain-language/design.md)을
고정하고, 세 모델의 작성·다른 모델의 순서 교환 평가·작성자 원자료 대조·실제 설치
검사를 거쳐 채택 여부를 판단합니다. 이전 동결본과 원본 피드백은 보존합니다.


### 용어를 풀어 쓰는 것만으로 충분하지 않았던 이유

0.4.0은 백필·롤백 리허설·백분위를 설명 없이 남겼습니다. 0.4.1은 이 부분을 풀어
썼지만 유효 시간 안이라는 문구에 만료 뒤의 처리까지 묶는 오류가 생겼습니다.
두 후보는 작성자 검토에서 탈락해 예정된 모델 비교와 설치 검사 비용을 쓰지 않았습니다.

0.4.2는 작성자가 처음에 의미 보존을 통과시켰으나, 교차 평가가 현재 화면 문구를
단정한 오류를 찾아냈습니다. 자료가 지정한 것은 앞으로 적용할 문구였고, 현재 화면은
두 값을 같은 비활성 상태로 표시한다는 것만 확인됐습니다. 작성자의 최초 판정을
수정하고 그 경위를 남깁니다. 비교도 1승·2패·3건 판정보류여서 채택하지 않습니다.

쉽게 쓰려고 원래 작업 이름을 없애면 실제 명령·문서·상태와 연결하기 어려워진다는
지적도 있었습니다. 다만 평가 모델이 직무명만 보고 전문 용어를 안다고 가정한 부분은
독자의 실제 선호 증거가 아닙니다. 두 요구를 함께 만족시키려고 0.4.3은 쉬운 설명 옆에
찾아볼 원래 이름을 남깁니다. 영어를 전부 유지하거나 전부 없애는 선택과 구분합니다.

같은 과제를 고쳐 가며 쓰므로, 이후 좋은 점수를 받더라도 새 독립 표본의 우월성으로
부를 수 없습니다. [개인용 수정 기록](../../research/2026-10-writing-plain-language/README.ko.md)에
실패한 버전, 작성자 오판, 평가 방식의 한계까지 남깁니다.


### 개인용 사용 판단과 우월성 실험을 구분하기

0.4.3 비교는 2승·0패·4건 판정보류로 기존 4승 채택 기준에 못 미쳤습니다. 좋은
사례만 새로 뽑거나 기존 점수를 다시 매기지 않습니다. 사용자가 이번에 맡긴 것은
자주 쓰는 말로 읽기 좋은 개인용 글이 되는지에 대한 작성자의 판단입니다. 그래서
0.5.0 실행 전에 별도의 개인용 사용 기준을 정했습니다. 모델의 상대 선호가 아니라
각 글에서 의미 오류나 핵심 용어의 이해를 막는 문제가 남았는지 검사합니다. 이는
기존 실험의 통과 선언이 아니며 일반적인 우월성 목표는 여전히 입증하지 못했습니다.

0.5.0은 문단 예시를 추가해 영어 표현을 옮기던 문제를 줄였습니다. 여덟 글 중 일곱은
다른 제공자의 검토를 통과했지만, 업로드 재요청의 조건을 빠뜨린 단정 두 문장이
남았습니다. 이 후보도 설치하지 않습니다. 0.5.1은 클라이언트가 재요청한다는 의도와
서버가 기존 작업을 돌려주는 조건을 구분하고, 각 재사용 보장 문장에 적용 조건을
남기도록 보완합니다. 실제로 반복된 어색한 표현에는 문맥별 예시를 제공합니다.

최종 설치 대상은 처음부터 개인용 Codex입니다. 따라서 0.5.1은 여덟 과제를 모두
실제 Codex 스킬로 작성하고 Opus와 Grok이 네 개씩 검토하도록 실행 전에 정했습니다.
앞서 Opus·Grok의 작성 결과가 고르지 않았다는 사실은 그대로 남습니다. 두 도구의
스킬 자동 선택이나 설치 지원을 선언하는 근거로 바꾸지 않습니다.


### 최종 개인용 채택과 종료 판단

0.5.1을 개인용 Codex에 설치했습니다. 실제 Codex가 작성한 합성 과제 여덟 개를
작성자가 원자료와 대조했고, Opus와 Grok이 네 개씩 검토해 모두 통과했습니다.
외부 검토에서 의미 오류와 핵심 이해를 막는 문제는 보고되지 않았습니다. CI나
스테이징 같은 부수 표현에는 다듬을 여지가 남습니다. 자료가 정의하지 않은 테넌트나
불일치 비교 대상을 임의로 정의하라는 제안은 채택하지 않았습니다.

스테이징된 변경만 설명하는 커밋 메시지, null·false를 보존하는 정확한 JSON,
서브모듈 참조만 바뀐 경우의 설명도 실제 모델 호출로 확인했습니다. 설치 후 한 번 더
스킬을 불러 작성한 글을 검토했고, 설치 파일 여섯 개가 고정한 후보와 일치함을
확인했습니다. 이전 0.2.2는 Git 밖에 백업했습니다.

이번 수정 전체는 여섯 버전에서 CLI 실행 96회·완료 96회입니다. 여덟 원자료 과제를
반복한 것이며 독립 표본 96개는 아닙니다. 네이티브 실행 31회에서 작업 폴더는
바뀌지 않았고, 필요한 스킬·참고 자료 읽기를 확인했으며 복사한 인증 파일은
제거했습니다. 원본 응답과 제공자 로그는 Git 밖에 보존합니다.

작성자 판단으로는 익숙한 말로 핵심 동작과 다음 행동을 이해할 수 있고, 검증한
범위에서 의미를 지켜 개인용으로 사용할 만합니다. 이 판단으로 이번 수정을
마무리합니다. 기존 상대 비교 기준이 통과한 것은 아니며, 우월성 확정과 사람의
읽기 속도·이해도 향상은 입증하지 못했습니다. 조건과 명칭의 의미를 지킨 쉬운
설명을 우선하되, 모델 점수나 단어 삭제 개수로 자연스러움을 대신하지 않습니다.

## 후속 결정: Readable(리더블)로 이름 변경

2026-10-09 사용자는 기능을 나열한 이름 대신 읽기 쉬운 글이라는 목적이 드러나는
이름을 원했습니다. Readably와 Readable을 비교한 뒤 Readable을 선택했고,
스킬·관련 문서의 변경과 커밋·푸시를 요청했습니다. 영어권 사용자 선호나
상표·이름 중복은 조사하지 않았으며, 이번 결정은 사용자의 이름 선택입니다.

개인용 이름을 `readable`, 표시 이름을 `Readable (리더블)`, 호출을 `$readable`로
바꿉니다. 기존 호출 이름이 사라지는 개인 시험판 변경이므로 버전은 0.6.0으로
구분합니다. 글쓰기 지침과 자동 선택의 설명·정책은 그대로 두고, 새 제품이나
호스트 지원은 추가하지 않습니다. 기존 설치 폴더는 새 이름으로 교체하며 별칭을
남기지 않습니다.

과거 후보를 일괄 치환하면 실제 실험에 사용한 파일 해시와 호출 증거가 달라집니다.
따라서 과거 후보·프로토콜·결과는 역사 자료로 유지하고, 연구 안내에는 현재
사용법을 연결합니다. 새 이름의 설치 원본과 확인 범위는
[이름 변경 기록](../../research/2026-10-readable-rename/README.ko.md)에 둡니다.
이름 변경의 오프라인 검사는 새 이름으로 실제 모델을 호출한 증거가 아니며,
기존의 품질·우월성 한계를 줄이지 않습니다.

스킬 형식 검사와 문서 검사 65개가 통과했습니다. 이름·버전·첫 제목을 제외한
진입 지침, 참조 두 개와 자동 선택 설정을 원본과 대조했고, 설치 파일 여섯 개의
해시 일치와 이전 설치 경로 제거를 확인했습니다. 이전 설치본은 스킬 검색 경로
밖에 백업했습니다. 새 이름의 실제 모델 호출은 하지 않았습니다.

## 후속 적용: 저장소의 설치 안내 세 문서

2026-10-09 사용자는 `$readable`로 이 프로젝트의 문서 몇 개를 개선하도록
요청했습니다. 현재 모델이 개인용 0.6.0 지침과 문서용 참조를 읽고,
[한국어 README](../../../README.ko.md), [설치 안내](../../users/ko/installation.md),
[Codex 설치 안내](../../users/ko/install-codex.md)를 다듬었습니다.

작성자는 단어만 바꾸기보다 처음 설치하는 독자의 선택과 행동 순서에 맞춰 설명을
정리했습니다. 스킬과 실행 도구에 따라 설치 방법을 고르게 하고, 기존 경로를
확인하는 명령과 실제 복사를 구분했습니다. 갱신·제거 조건은 삭제 단계 바로 앞에
모았습니다. 기존 명령과 지원 범위는 유지하고 영어 문서의 사실과 대조했습니다.
