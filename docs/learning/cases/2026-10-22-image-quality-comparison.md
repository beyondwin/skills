# 이미지 스킬이 결과 품질을 높이는가?

결정일·기록일: 2026-10-22. 관련 작업: image-workbench.
근거 성격: 사용자가 승인한 Grok CLI 실제 생성 비교. 합성 요청만 사용하며 생성물과
제공업체 응답 원본은 저장소 밖 로컬 평가 폴더에 보관한다.

## 시작한 문제

사용자는 일반 생성과 스킬 적용의 유의미한 차이, 고품질 생성 전략, 실제 검증과
개선을 요청했다. [이전 사례](2026-10-21-image-inspection-convergence.md)는 검수
종료를 확인했지만 새 이미지의 잘림은 남았다. 따라서 검수 정확도와 이미지 자체의
품질 개선을 분리해야 한다.

## 대안과 사전 판정 기준

프롬프트를 무조건 길게 만들거나 좋은 결과만 선택하는 대신, 동일 요구·모델·횟수의
일반 경로와 현재 스킬을 비교한다. 일반 경로에도 모든 프로젝트 조건을 제공한다.
세 가지 합성 과제를 각 두 번 생성한다. 각 경로는 첫 후보 한 장만 허용하고 수정본도
같은 여섯 조건에서 비교한다. 같은 과제 반복은 독립된 여섯 도메인이 아니다.

필수 조건 통과(잘림, 개수, 여백, 원치 않는 문자), 미적 완성도 1–5(형상, 재질·빛,
구도, 표현의 일관성), 작업 완료·호출 수·시간을 분리한다. 평가자는 경로를 가린
파일과 원래 요구만 본다. 평균 미적 점수 차이 0.5 이상이면서 표준오차 두 배를
넘고 필수 조건 통과가 나빠지지 않을 때만 이 표본의 품질 향상으로 판단한다.
작은 개발 표본이므로 일반적인 통계적 우월성을 주장하지 않는다.

수정은 실제 실패에 한정한다. 초기 12회, 수정본 6회, 새로운 전이 과제 최대 4회,
표적 수정 최대 2회로 최초 이미지 호출 상한은 24회로 정했다. 추가 스모크의 brief·경계 검사는
이미지를 생성하지 않는다. 입력·스킬 전체 리소스를 고정하고 세션별 근거를 남긴다.

## 확인한 결과

Grok CLI 1.0.62, 실제 에이전트 모델 `grok-4.7-build/high`에서 일반 6장과
기존 2.1.2 스킬 6장을 비교했다. 이미지 도구의 내부 모델명은 공개되지 않았다.
완성도 평균은 일반 3.98, 스킬 4.17/5였고 차이 0.1875는 사전 기준에 못 미쳤다.
필수 조건·화면비 전체 통과는 각각 2/6이었다. 세 과제만의 작은 탐색 실험이며,
두 평가자는 모델이다. 사람 선호도나 일반적인 우월성을 입증한 결과가 아니다.

병 이미지 네 실행은 지원하지 않는 4:5를 보내 거절된 뒤 3:4로 재시도했다.
이는 한 번만 호출하기로 한 조건과 최종 화면비를 모두 어긴 실패다. 좋은 그림이
나왔다는 이유로 제외하지 않았다. 미적 점수는 기술통계로 남기되 공정한 한 호출
비교로 해석하지 않는다. 거절 호출과 실제 생성 장수, 에이전트 비용과 이미지 과금도
분리한다. 이미지 제공자의 실제 과금은 확인하지 못했다.

첫 수정안은 구도 지침을 첫 프롬프트부터 확장했으나, 6장 평균이 3.875로 내려갔고
찻상 조건 통과도 2/2에서 1/2로 악화됐다. 따라서 전면적인 프롬프트 확장은 폐기했다.
화면비 확인·명시적 변환은 병 두 장을 한 호출씩으로 4:5 납품하는 데 성공했지만,
미적 향상으로 해석하지 않는다. 같은 배 이미지의 읽기 전용 감사에서는 완전 가시성
요구는 거절하고, 가려짐을 허용한 개수 요구는 수용했다. 입력 해시도 유지됐다.

최종 방향의 첫 보정은 여전히 잎을 가렸고, 사전 선택한 새로운 둥지 과제 한 장은
두 평가자의 필수 조건·화면비 검사를 통과했다. 계획한 또 다른 전이 과제인 램프는
실행하지 않았다. 24회가 소진된 후 정확한 수직 시점 보정 두 회를 별도 개발 확장으로
선언하고 실행했다. 실행 전에 변경 이유와 추가 예산을 기록했으며, 비교 통계에
합치거나 최초 24회 상한을 지킨 것처럼 보고하지 않는다.

추가 두 장은 가려짐을 해결했지만, 한 장은 잎이 4개로 늘어 개수 조건을 어겼다.
나머지 한 장은 두 평가자의 필수 조건·화면비 검사를 통과했다. 생성 에이전트도
개수 실패를 거절했고, 통과 이미지의 시점·사진 같은 표현 한계를 보고했다.
최종 합계는 이미지 도구 26회 호출, 22장 생성, 4회 거절과 읽기 전용 모델 검사
6회다. 총 28세션이 최종 응답으로 끝났고 고정 리소스 해시가 유지됐으며 임시
인증 사본은 모두 삭제됐다. 이후 성공 한 장도 반복 성공률을 보장하지 않는다.

오프라인 전체 검사는 원본 체크아웃의 gitignored 퇴역 제품·테스트 폴더 5개로
시작 단계에서 막혔다. 기존 폴더는 보존하고, 현재 추적 파일과 신규 문서의 복사본에
별도 Git 인덱스를 만든 뒤 `python3 scripts/verify.py`를 실행해 종료 코드 0을
확인했다. 단위 테스트 642개, 제품 계약·변이 검사, Python 컴파일을 포함하며
제공자 호출은 없다. 실행 환경은 macOS·Python 3.14이고 제품 Python 코드는
수정하지 않았다. 마지막 기록·문서 변경은 해당 검사와 링크 검사로 따로 확인한다.
범용 skill-creator 검사기는 기존 `compatibility` 필드를 변경 전후 모두 거절하지만,
저장소 계약이 요구하는 필드이므로 유지했다.

## 구현 방법

[SKILL.md](https://github.com/beyondwin/skills/blob/6564ed5f039f3a7c1b1729d0652cc8015ab80f2d/skills/image-workbench/SKILL.md)는 상세한 첫 요청을 보존하고,
실제 결함을 본 뒤 [공간 보정 지침](https://github.com/beyondwin/skills/blob/6564ed5f039f3a7c1b1729d0652cc8015ab80f2d/skills/image-workbench/references/image-spec.md)을
적용하도록 좁혔다. [검수 기준](https://github.com/beyondwin/skills/blob/6564ed5f039f3a7c1b1729d0652cc8015ab80f2d/skills/image-workbench/references/quality-rubric.md)은
개수와 전체 윤곽의 가시성을 구분한다. 현재 도구의 지원 화면비를 먼저 확인하고,
안전한 명시적 변환·허용된 근사·hold 중 실제 가능한 결과를 보고한다. 거절된 호출도
사용자가 정한 도구 호출 예산에 포함한다. 버전은 PATCH 2.1.3이다.

자세한 실험 방법·집계·한계는 [연구 기록](../../research/2026-10-image-quality/README.md)에
있다. 생성 이미지·실제 호출 원문·해시 목록은 로컬 근거 묶음에만 보관한다. 저장소
문서만으로 픽셀을 재채점할 수는 없다. 마지막 reference 수정의 검증은 전체 리소스
해시와 별도 실행으로 연결하며, SKILL 본문 스모크 해시만으로 대신하지 않는다.

## 유지와 종료 판단

스킬을 켜면 평균적으로 더 아름답다는 약속은 채택하지 않았다. 기존 요청 보존,
정확한 조건 검수, 화면비 처리, 관찰된 결함에 한정한 보정만 유지한다. 원래 비교,
폐기한 수정안, 실패한 보정, 후속 성공을 모두 남겨 결과 선택의 영향을 드러낸다.
배포·태그·푸시는 하지 않았다.

## 다음에 쓸 배움

현재 해석은 다음과 같다. 품질 전략은 용도·구도·필수 가시성·재질과 빛을 구체화하고,
첫 후보를 그대로 검수한 뒤 실제 원인을 좁혀 수정하는 것이다. 여러 후보를 허용했다면
조건을 통과한 후보 중에서 고르되 모든 후보와 비용을 남긴다. 선택된 좋은 한 장은
달성 가능한 결과의 예시이지 평균 향상의 증거가 아니다. 더 긴 프롬프트나 반복 횟수
자체를 품질 보증으로 삼지 않는다. 이 판단은 세 합성 과제와 제한된 후속 실험에
근거하며, 편집 보존·시리즈 일관성·다른 호스트로 일반화하지 않는다.
