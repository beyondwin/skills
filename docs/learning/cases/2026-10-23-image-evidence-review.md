# 근거를 분리하는 검수가 개수·가림 오판과 정상 후보 탈락을 줄이는가?

결정일: 2026-10-23
기록일: 2026-10-23
관련 작업: image-workbench
결과: 개발 중. 효과와 채택 여부는 아직 미확인.
근거 성격: 당시 사용자 요청, 이전 실험 원본과 판정 기록, 현재 실행 계획.

## 시작한 문제

앞선 2.1.5는 보정 조건 보존만 고쳤다. 개수·가림 검수 개선안 세 가지는
실패했고 새 이미지의 정확도도 10/12에서 9/12로 낮아졌다. 사용자는 검수 방식
자체를 다시 설계해 실제 효과를 확인하고, 적절히 커밋하면서 끝까지 개선해
달라고 요청했다. 기존 로컬 변경은 먼저 `6e9eef6`으로 보존했다.

## 대안과 선택

확대 이미지나 설명을 더 추가하는 방향은 이미 실패했다. 원본·상세 이미지가
실제로 모델에 전달됐는지 바이트 해시도 확인했으므로 전송 누락을 원인으로
가정하지 않는다. 서버 내부의 이미지 처리는 미확인이다.

이번 가설은 조건 해석과 관찰, 탈락 결정을 분리하면 오류를 줄일 수 있다는
것이다. 원문에서 대상·부품·지지면·배경을 구분하고, 실제 보이는 항목을 위치별로
나열한 뒤 요구 수와 비교한다. 완전 가시성은 접점의 앞뒤 관계와 끊기는 경계를
따로 확인한다. 탈락 전에는 원문 조건과 국소적인 관찰 근거를 연결하고, 정상적인
배경이나 부품이라는 해석을 확인한다. 미적 선호는 정상 후보의 탈락 근거가 아니다.

별도 검수자는 같은 모델의 오류를 반복할 수도 있고 비용을 늘린다. 현재는
추가 필수 의존성으로 넣지 않고, 구조화된 검수가 실패하면 같은 총예산 안에서
이전 판단을 숨긴 별도 컨텍스트 검수를 대안으로 시험한다.

## 검증과 판단 기준

이전에 본 22장은 개발용이다. 새로운 24장은 실제 Grok 생성 후 두 익명
검수자가 조건과 이미지만 보고 판정한다. 의도적으로 넣으려던 실패가 실제로
그려졌다고 가정하지 않는다. 정상 배경·일체형 부품과 실제 별도 물체를 함께
넣어 단순히 관대해진 것인지도 확인한다. 보류나 미완료로 오류를 숨기지 않는다.

기존 2.1.5와 같은 입력·시간·턴·호출 한도로 비교하고, 실패 후보를 통과시키는
오류와 정상 후보를 탈락시키는 오류를 각각 측정한다. 새 평가 결과를 보고
수정하면 그 자료는 개발용이 되며, 다음 판정에는 새로운 평가집이 필요하다.
구체적인 사전 기준과 실제 결과는 [연구 기록](../../research/2026-10-image-evidence-review/README.md)에 둔다.

## 확인한 결과

개발안 A의 첫 네 장은 기존판과 모두 맞혀 우위가 없었다. 이어진 가림 실패 두
장에서는 A가 모두 통과시켰다. 최종 이유에는 잎의 개수와 화면 안 위치만 있고,
테두리에 가려지는 아래쪽 경계의 근거는 없었다. 전부 실패한 묶음을 보류해야
한다는 필수 기준을 이미 실패했으므로 A는 최종 후보로 채택하지 않는다. 남은
실행도 끝까지 보존해 전체 점수와 비용을 기록한다.

다음 개발안에서는 탈락 근거뿐 아니라 통과시키는 각 필수 조건의 관찰 근거를
요구한다. 완전 가시성을 화면 밖으로 잘리지 않음이나 개수 식별로 대체하지 못하게
하는 것이 다음 가설이다. 효과는 아직 측정하지 않았다.

B도 두 장 중 한 장을 틀려 중단했다. 이번에는 경계가 보인다는 구체적인 설명을
붙였지만 실제 픽셀과 달랐다. 원문과 익명 이미지만 받은 새 검수자도 두 장 모두
가림 실패로 판정했다. 근거를 적는 칸만 늘려서는 지각 오류를 고치지 못했다.

다음 실험은 같은 Grok 모델의 새 컨텍스트 두 개로 관찰과 판정을 나눈다.
관찰자는 원하는 개수나 합격 조건을 모르고 물체·부품·접점의 앞뒤 관계만
기록한다. 판정자는 수정하지 않은 관찰 기록과 원문 조건·원본을 대조한다.
총 턴과 시간은 기존 묶음 예산 안에서 나눈다. 가림 두 장만 맞히는 것으로
끝내지 않고 정상 테이블을 포함한 네 장도 함께 통과해야 한다. 먼저 이 가설을
검증하며, 효과가 있어도 실제 스킬에서 독립 관찰자를 호출하는 실행 경로를
확인하기 전에는 제품 효과라고 주장하지 않는다.

분리 관찰 실험 C는 두 관찰자 모두 이미지 처리 도구와 라이브러리를 찾느라
12턴을 소진했고 정상 관찰 기록을 만들지 못했다. 최종 판정은 실행하지 않았다.
이는 지각 가설의 성공이나 실패가 아니라 실행 실패다. 다음 D 실험에서는
관찰자의 도구를 원본 읽기와 관찰 기록 쓰기로만 제한한다. 같은 여섯 장과
누적 예산을 유지한다. 도구 제한도 개입의 일부로 기록하고, 최종 비교에서는
기존판에 동등한 도구 선택권을 제공해야 한다.

개발용 조약돌 묶음에서는 양쪽 모두 실행 범위를 벗어났다. A는 격리 임시 폴더
밖의 추측 경로를 읽으려다 실패했고, 기존판은 공용 임시 폴더에 경로 포인터를
썼다. 두 묶음은 주평가에서 검증불가로 남기고 시각 판정만 보조값으로 분리한다.
실패한 실행을 다시 돌려 정상 결과로 교체하지 않는다.

D의 실제 초기화 로그에서는 도구 제한이 적용되지 않았다. CLI 인자에 쓰는
일부 도구 이름이 호출 원장의 이름과 달랐고, 잘못된 이름을 받으면 전체 도구를
남기는 동작이었다. 기존 비교도 같은 영향을 받았다. 실제 이미지 호출은 모두
0회였지만, 도구가 구조적으로 차단됐다는 설명은 철회한다. D의 한 관찰자에는
기본 스킬 설명도 추가로 노출됐다. D는 채택 근거로 쓰지 않고 판정 단계를
실행하지 않는다. 새 호출 전에 올바른 도구 ID와 기본 스킬 제외 설정을 확인하고,
최소 실행으로 실제 초기화 상태를 검증한다. 준비 시점의 목록만으로 실행 환경을
보장할 수 없었다.

A의 22장 비교도 끝났다. 범위 위반을 포함한 보조 판정 점수는 기존판 16/22,
A 17/22였지만, 가림 오수락 두 건은 그대로였고 후보 선택은 6/8에서 5/8로
낮아졌다. 실행 비용도 늘었다. 범위 위반으로 검증할 수 없는 항목은 기존판
9개, A 5개다. 서로 다른 검증 부분집합의 점수를 개선으로 해석하지 않는다.
A는 채택하지 않는다.

실행 환경을 고친 E에서는 한 장씩 독립 관찰했다. 여섯 실행 모두 도구·스킬
격리와 원본 전달은 확인됐지만 네 개가 100초 제한을 넘겼고 판정 단계는
실행하지 않았다. 정상 완료한 테이블 두 장도 지지대 개수를 틀렸다. 다음 F는
이미지 전체 설명을 요구하지 않고 원문에서 뽑은 물리적 질문 하나만 묻는다.
테이블의 지지대 끝점과 바닥 관계, 또는 잎 경계의 앞뒤 관계를 관찰하되 요구
개수나 정답 위치는 알려주지 않는다. 개별 시간은 200초로 조정하되 판정까지
포함한 묶음 전체 30턴·900초는 유지한다.

F도 실패하면 Grok 검수 프롬프트를 더 늘리는 방향은 중단한다. 사용자가
Grok CLI로 지정한 것은 이미지 생성이므로 Codex 검수와 Grok 생성을 분리하는
실제 사용 경로를 별도로 비교할 수 있다. 이 경우 기존판도 같은 Codex 모델과
effort로 다시 실행한다. 검수 모델을 바꾼 효과를 스킬 개선으로 계산하지 않는다.

실패한 B의 설치본 변경은 되돌렸다. 실험용 고정 사본과 패치는 보존했고 진행 중
실행도 그 사본만 사용한다. 검증을 통과한 새 변경이 나오기 전까지 설치본은
커밋된 2.1.5이며, 실험용 2.1.6은 출시하지 않는다.

Codex 비교는 품질 결과를 보기 전에 별도로 정한다. 기존판과 고정 B 사본 모두
현재 호스트에서 실제 확인한 `gpt-6-astra/ultra`를 사용하며, 동일한 배 두 장과
테이블 네 장부터 비교한다. 입력·조건·도구·예산을 같게 두고 Grok 결과와 합산하지
않는다. 기존판도 모두 맞히면 스킬 개선으로 부르지 않는다. 원본 전달과 설정을
확인하는 최소 실행은 품질 질문이 없고 평가 점수에도 넣지 않는다.

F도 채택하지 못했다. 관찰 여섯 개는 정상 완료했지만 판정 두 묶음은 모두
남은 턴을 소진했다. 관찰까지 합산한 예산은 각각 30턴·772.788초와
30턴·786.194초였다. 관찰 원문이 실제 읽혔고 같은 모델이 실행된 것도 확인했다.
배 판정은 확대 진단으로 원본 픽셀 검수 조건도 어겼다. 테이블의 미완료 보고서는
정상 세 장까지 전부 탈락시켰다. 관찰을 끝내는 실행 문제는 줄었지만 지각이나
최종 판정 품질이 좋아졌다는 근거는 아니다. Grok 검수 문장을 더 늘리는 실험은
여기서 중단하고 별도 Codex 비교를 진행한다.

오프라인 통과나 프롬프트 길이 증가를 품질 개선으로 세지 않는다.
최종 기록에는 실패한 후보, 정상 완료 여부, 실제 모델, 비용·호출 수, 조건 보존과
이미지 품질의 차이, 채택 또는 폐기 이유를 함께 남긴다.

Codex 비교도 기존판과 B 모두 4/6, 오수락 0건·오탈락 2건으로 동률이었다.
네 실행의 원본 전달·모델·격리·도구 범위는 독립 검증을 통과했다. 두 실행 모두
정상 테이블에서 네 발을 명시적으로 세었지만, 뒷다리 외곽 전체가 보이지 않는다는
이유로 탈락시켰다. 이 경우는 개수 지각보다 요구조건을 더 엄격하게 만든 문제다.
최초 원문과 요약 조건은 현재 입력까지 바뀌지 않았고, 최초 익명 심사도 부분
겹침을 밝히면서 별도로 보이는 다리와 발을 인정했다. 정답표는 바꾸지 않는다.
원문 해석의 모호함이 있으므로 이 개발 표본만으로 일반적인 우위를 주장하지 않는다.

다음 G는 화면 안에 들어오는 전체성, 각 부품의 직접 식별 가능성, 명시적으로
요구한 완전 무가림을 분리한다. 전체 물체의 수식어를 각 부품 외곽으로 확대하지
않고 원문 강도에 맞춰 판정한다. 관찰 표나 별도 모델, 생성기 변경은 추가하지
않는다. 같은 여섯 장을 전부 맞히고 가림·부품 누락도 계속 잡아야 이후 비교로
진행한다. 통과하면 양쪽을 새로 실행하는 22장 비교와 새 이미지 평가를 거친다.
설치본은 효과가 확인되기 전까지 2.1.5를 유지한다.

G의 여섯 장 검사는 6/6, 오수락·오탈락 각각 0건, 후보 선택 3/3으로 통과했다.
기존판의 4/6·선택 2/3과 비교하면 정상 두 장을 복구하면서 가림 두 장과 부품
누락 한 장을 계속 잡았다. 독립 실행 감사와 원본 전달도 통과했다. 과거 원본과
기존 대조 실행을 재사용한 개발 결과이므로 최종 효과로 확대하지 않는다.
이제 G를 그대로 고정한 채 양쪽을 새로 실행하는 22장 비교를 진행한다.

새 이미지에서는 스킬 없는 검수도 같은 조건으로 비교한다. 주 비교는 기존판과
G이며, 일반 방식과의 비교는 별도로 같은 효과 기준을 충족해야 우위를 말한다.
일반 방식과의 결과로 주 비교 실패를 대신하지 않는다. 감사 뒤 보고서가 바뀌는
허점을 막기 위해 원본 실행의 최종 응답·출력 파일·보고서 일치를 채점 시 다시
확인했고 변조를 잡는 회귀 검사 다섯 개도 통과했다.

최종 생성 검증은 이전의 조명·조약돌·카라페 요청 세 개를 그대로 사용한다.
일반·기존판·G 각 세 과제이며 과제당 이미지 호출은 실패를 포함해 최대 두 번이다.
모든 방법에서 Codex가 계획·검수하고 사용자가 지정한 Grok CLI가 그린다.
스킬 본문 비교와 실제 설치 스킬의 활성화 확인은 별도로 수행한다.
보정 요청의 실제 전달 문구와 조건 보존, 원본에서 최종 파일까지의 해시,
모든 후보의 관찰, 종료 시 하위 프로세스와 임시 인증 정리까지 검증한다.
정상 첫 후보를 불필요하게 다시 만드는 비율과 최종 사용 가능 전달이 기존판보다
나빠지면 통과시키지 않는다. 세 과제의 생성 변동을 검수 규칙의 미적 효과로
해석하거나 실패한 과제를 새 요청으로 교체하지 않는다.

22장 전체를 양쪽 새 세션으로 다시 검수한 결과, 기존판 19/22에서 G 22/22로
개선됐다. 오수락은 0건을 유지했고 정상 후보 오탈락은 3건에서 0건, 후보 선택은
7/8에서 8/8로 바뀌었다. 세 번째 오탈락은 표면 장식을 확신하지 못해 정상
카라페를 보류한 경우이며, 정해 둔 지표대로 오탈락에 포함했다. 개수·가림은
기존판도 맞혔으므로 이 단계의 개선은 정상 후보 보존이다. 12개 실행과 최종
집계 연결을 독립 검증했다. 고유 이미지 개선 3건·퇴행 0건의 exact paired
p값은 0.25로, 일반적인 우위를 주장할 근거는 아니다.

G를 고정한 채 새 이미지 24장 생성 단계로 진행한다. 정답 의견이 갈리는
항목도 남기고, 명확한 합의 항목의 점수와 전체의 최저·최고 가능 범위를 함께
보고한다. 다른 조건에 통과·실패 충돌이 있으면 공통 실패가 있어도 논쟁 항목으로
남긴다. 논쟁 후보의 선택이나 논쟁 후보만 남아 있는 풀의 선택 보류를 성공으로
계산하지 않는다. 생성 의도를 정답으로 사용하지 않는다.

새 이미지 생성은 첫 두 시도 뒤 원본 열람 누락으로 자동 중지됐다. 이미지 자체는
각각 한 번 생성됐고 프로젝트 복사본도 원본과 같았지만 생성 모델이 `read_file`로
다시 열지 않았다. 이 실패를 정상으로 바꾸지 않는다. 픽셀·정답을 열기 전에
아직 실행하지 않은 22개만 같은 요청·환경으로 이어가도록 절차를 명시했다.
누락은 검수용 원본의 존재와 별도로 기록하고, 익명 평가자가 모든 원본을 직접
연다. 최초 두 장을 재생성하거나 교체하지 않으며 다른 실행 오류는 계속 중단한다.
이 자료로 생성 후 전달 절차의 성공을 주장하지 않는다.

새 원본 24장을 모두 확보했다. 실제 생성도 24회이며 재시도·교체·보정은 없었다.
원본과 프로젝트 복사본은 전부 같고 중복도 없었다. 생성 모델의 별도 열람은
24건 모두 누락됐으므로 원래 생성 절차 성공은 0/24로 남긴다. 별도 원본 무결성
검사만 통과했다. 런타임 감사자가 실수로 한 생성 문구를 본 사실도 기록했고
품질 판정에는 참여하지 않는다. 새 검수자 둘은 원문 조건과 익명 원본만 받는다.

최종 전달 실험에서는 Grok 자식은 그리기와 원본 전달을, Codex 부모는 모든
후보의 직접 검수를 맡는다. 자식의 별도 미리보기를 중복 요구하지 않지만
부모의 원본 검수는 미선택 후보까지 필수다. 이 역할 분리는 실제 호출 전에
정했으며 앞선 열람 누락을 소급해서 성공으로 바꾸지 않는다.

두 익명 평가자는 24장 중 23장(정상 10·실패 13)에 합의했고 조건 96개 중
95개가 일치했다. 남은 배 한 장은 가림 판정이 갈렸다. 비교 모델 호출 전,
정답이 불확실한 후보만 남은 풀에서는 신중한 보류를 벌점 처리하면서 명백한
실패 후보 선택이 불확실 플래그를 피할 수 있는 채점 결함을 발견했다.

원래 엄격 기준은 그대로 별도 보고하고, 수정 기준에서는 같은 풀의 선택값이
대조군과 정확히 같을 때만 비교상 동률로 허용한다. 이를 정답이나 개선으로
세지 않는다. 실패 검출에서도 대조군이 두 반복 모두 모든 명확한 실패를 확인해
맞혔다면 개선안은 그 상한을 유지해야 한다. 이는 검출 향상이 아니며 별도로
표시한다. 미확인·누락은 상한 달성으로 세지 않는다. 반복마다 순증 2장, 90%
이상 정확도, 오수락·오탈락 비악화 등 나머지 기준은 유지한다. 원본·정답·후보·
요청·모델·예산·순서는 바꾸지 않았다. 이 변경은 정답 합의 후, 비교 결과를
보기 전에 독립 검토한 측정 설계 수정이다. 최초 사전계획 통과로 포장하지 않는다.

새 검수 결과를 열기 전에 저장소의 채택 기준도 따로 고정했다.
`skill-practices.md`는 “A difference smaller than about two standard errors is
‘no measured difference’ and changes nothing.”이라고 정한다. 작은 차이를
일반적인 우위로 표현하지 않는 것만으로는 이 기준을 충족하지 못한다.
개발 22장의 순증 3건은 여기에 미달하며, 새 비교의 반복별 최소 순증 2건도
그 자체로 채택 근거가 되지 않는다. 같은 이미지의 반복은 새 독립 표본이 아니다.

고유한 확정 이미지마다 두 반복의 후보 정답률에서 대조 정답률을 뺀 값을
구한다. 그 차이의 평균, 표본 표준편차와 `SE = 표본 표준편차 / sqrt(고유 이미지 수)`를
계산하고, 표본이 두 개 이상이며 평균이 양수이고 `평균 >= 2×SE`일 때만 이
추가 기준을 통과한다. 미완료·미확정 관찰은 분모에서 빼지 않고 정답으로
세지 않으며, 정답 자체가 분쟁인 이미지는 개선 근거로 쓰지 않는다. 기존판과
일반 방식에 각각 적용하고, 두 비교 모두 통과해야 예정한 양쪽 대비 개선과
채택을 뒷받침한다. 정확한 paired p값은 별도로 공개하며 새 p값 기준은 만들지 않는다.

이는 원래 strict 기준이나 앞서 기록한 amended 기준을 바꾸는 것이 아니라
실제 채택에 필요한 추가 조건이다. 실행 감사·활성화·최종 생성 검증의 실패도
대신할 수 없다. 같은 요청이나 검수 세션에 속한 이미지 사이의 의존성은 이
근사 계산에 반영되지 않으므로 일반적 우위나 사람의 선호까지 입증하는 것은
아니다. 각 결과를 분리해 공개한다. 실행 입력·고정 사본·정답·일정·예산은
그대로이며, 작은 효과만 나온다면 G는 미채택으로 유지한다. 효과가 나올 때까지
선별적으로 재실행하지 않고, 후속 평가가 필요하면 새 설계를 먼저 고정한다.

고정 G의 네이티브 지원 검사 다섯 건도 완료했다. Grok의 명시·암시 호출,
일반 그림 요청 경계, 실제 한 장 출력과 Codex의 명시 호출을 독립 감사했다.
Grok은 15턴·세션 합 170.388초·이미지 1회, Codex는 3응답·38.459초·이미지
0회였다. 이는 실제 설치본 발견과 본문 전달, 기본 출력 확인이며 검수 품질이나
편집 보존의 증거는 아니다. 자동 본문 확장과 최종 메시지 필드 차이로 발생한
초기 파서 실패는 보존하고, 정확한 원문·최종 JSON 검사만 보정했다. 재실행은
없었다. 검사기가 사용한 공용 임시 보고서 경로의 사전 상태는 확인하지 못해
완전 격리나 기존 파일을 건드리지 않았다는 주장은 하지 않는다.
