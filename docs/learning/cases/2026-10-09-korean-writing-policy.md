# 명확한 한국어 기술 글쓰기를 별도 스킬로 만들까?

결정일: 2026-10-09. 기록일: 2026-10-09.
관련 작업: 한국어 기술 글쓰기 연구와 `korean-writing-editor`의 역할 범위.
결과: 연구에 따른 제안입니다. 제품이나 설치된 지침은 바꾸지 않았습니다.
근거 성격: 사용자의 해당 요청, 제공된 비공개 아이디어 자료, 현재 저장소 계약,
재현한 로컬 테스트, 승인된 여러 호스트의 합성 실험입니다.
비공개 자료 자체는 저장소에 넣지 않고 해시와 보관 가능한 결과 요약만 남깁니다.

## 시작한 문제

사용자는 명확한 기술 글쓰기 원칙을 한국어 에이전트 답변, 문서, 커밋, PR, 인계에
적용하는 아이디어를 가져왔습니다. 다각도 평가, 테스트, 제안을 요청하면서 유용한
수준까지 자율적으로 진행하기를 원했습니다. 이후 실험의 이유·방법·결과도 체계적으로
관리해 달라고 요청했습니다. 이 요청이 제공된 자료에 들어 있는 모든 지침의 설치까지
승인한 것은 아닙니다.

## 당시 조건

의미, 근거의 상태, 출력 형식, 기존 글의 말투를 보존합니다. 기술 커뮤니케이션과
교사용 제품 문구는 구분합니다. 기존 `korean-writing-editor`는 제공된 원문의 교정용이며
새 글 작성용이 아닙니다. 이 저장소는 기본적으로 제품 추가를 허용하지 않습니다.

사용자는 합성 과제에 대한 Codex 호출 24회를 승인한 뒤 Cursor Grok 4.7, Claude CLI
Opus, 하위 에이전트를 추가했습니다. 공지한 실험 상한은 호스트별 실행 요청 24회였습니다.
이후 슈퍼파워스 사용을 금지했고 평가도 이를 사용하지 않고 진행했습니다. 비공개 원고나
제품 기록을 모델 과제로 사용하지 않았습니다.

## 대안과 선택

실제로 검토한 대안은 짧은 공통 정책, 별도 작성 스킬 또는 참조 문서, 한국어 편집기
확장, 필수 문자열 검사 훅이었습니다. 새 스킬이 필요하다고 가정하지 않고 추가 정책을
동일하게 통제한 일반 기준선과 비교했습니다.

현재 제안은 편집기의 역할 범위를 유지하고, 범용 린트 검사를 필수 통과 조건으로
만들지 않으며, 기존 지침에 빠진 공통 규칙만 시험 적용하는 것입니다. 근거 수집이나
분기 판단 실패가 반복되고 이를 해결할 가치가 확인되면 별도 작업 스킬을 다시 검토할 수
있습니다. 에이전트의 제안이며 사용자가 제품 출시를 승인했다는 뜻은 아닙니다.

## 구현 방법

상세 측정은 [연구 문서](../../research/2026-10-ko-clear-writing-eval/README.md)가
관리합니다. [실험 방법](../../research/2026-10-ko-clear-writing-eval/method.md)은 각 실험이
어떤 질문과 결정에 연결되는지 설명합니다. 실제 생성 전에 절차와 입력 해시를 고정하고,
제공업체별 실행 도구로 각 실행을 격리했습니다. 조건을 가린 출력 검토로 생성과 채점을
분리했으며 이견을 조정한 판단도 남겼습니다.

사례는 의도와 최종 판단을, 연구 폴더는 과제·실행 도구·결과 요약·한계를 관리합니다.
제공업체 응답 원본은 Git 바깥의 로컬 보관소에 둡니다. 자동 설치, 발행, 지속적인
사용자 설정 변경은 하지 않았습니다.

## 확인한 결과

제공된 자료의 테스트 41개와 연구 검사를 macOS 기본 Python 3.9.6에서 재현했습니다.
독립적인 경계 점검 15개에서는 구체적 결함 8개, 숫자 문법의 공백 1개, 알려진 근거·파서
한계 2개, 정상 동작을 확인하는 대조 사례 4개가 나왔습니다. 기존 테스트를 통과했다는
이유만으로 범용적인 의미 보존 검사를 신뢰할 수는 없습니다.

실제 모델 결과와 실행된 모델 식별자는 중복하지 않고 연구에서 찾아가도록 했습니다.
정책 전체를 입력에 넣은 8개 과제의 단회 실험입니다. 자동 스킬 선택, 사람의 이해도,
통계적 동등성은 측정하지 않았습니다. 특히 모든 지침을 한 번에 넣은 입력은 필요한
자료를 단계적으로 읽는 일반적인 사용 방식과 다릅니다.

## 유지와 종료 판단

연구, 짧은 실험용 정책, 재현 가능한 실행 도구, 구체적인 결함 보고는 보존합니다.
이 결과로 새 제품을 출시하거나 기존 편집기의 범위를 넓히지는 않습니다. 아직 보지 않은
과제에서 효용이 확인되면 전용 작업 흐름을 다시 검토하되, 실제 설치 환경에서의 발견과
근거 조회를 별도로 테스트해야 합니다.
