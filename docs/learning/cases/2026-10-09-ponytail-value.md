# Ponytail은 기존 작업 규칙 위에서도 추가 가치가 있을까?

검토일·기록일: 2026-10-09.
관련 작업: 외부 Ponytail 스킬의 지침, 주입 코드, 실험 근거 검토.
결과: 과잉 구현 억제의 조건부 가치는 인정하되, 현재 환경에서 전체 플러그인의
상시 사용을 정당화하는 추가 효과는 미측정입니다. 설치·제품 변경은 하지 않았습니다.
근거 성격: 공개 소스와 보고서, 공개 표 재계산, 로컬의 공급자 없는 재현.
새 모델 호출, 실제 호스트 세션, 사람의 이해도·장기 유지보수 측정은 없습니다.

## 시작한 문제

사용자는 Ponytail이 실제로 유의미한지 깊게 살펴보고 설명해 달라고 요청했습니다.
좋은 개발 원칙인지, 기본 에이전트보다 나은지, 이미 작업 규칙을 갖춘 환경에서도
설치할 가치가 있는지를 구분했습니다. 관련 맥락은
[작업 흐름 스킬 선셋 사례](2026-10-09-retire-workflow-skills.md)와
[일반 리뷰와 스킬 비교](2026-10-08-pre-sdd-review-value.md)에서 확인했습니다.
그 사례의 결론을 Ponytail에 그대로 적용하지 않았습니다.

## 당시 조건

검토 소스는 DietrichGebert/ponytail의 **5.1.0**, 커밋
`9cc65d03aa2da1db7121b912d03596409ee340b8`입니다.
공식 최신 성능 보고는 5 계열, 외부 JetBrains 실험은 **4.8.4** 대상입니다.
같은 버전의 상호 재현으로 보지 않았습니다.

## 구조에서 확인한 것

- [핵심 지침](https://github.com/DietrichGebert/ponytail/blob/9cc65d03aa2da1db7121b912d03596409ee340b8/skills/ponytail/SKILL.md)은
  범위 확인, 기존 코드 재사용, 표준 기능, 설치된 의존성, 읽기 쉬운 최소 구현의
  선택 순서를 제공합니다. 호출자·테스트·픽스처까지 완료하고 기존 구조를 지키도록 합니다.
  검증·데이터 손실 방지·보안·접근성을 삭제하지 말라는 제한도 있습니다.
- [시작 훅](https://github.com/DietrichGebert/ponytail/blob/9cc65d03aa2da1db7121b912d03596409ee340b8/hooks/ponytail-activate.js)은
  모드별 지침과 코드 지도를 문맥에 넣습니다. 의미 판단이나 정답 판정은 여전히 모델이 합니다.
  이 코드는 구현 품질을 강제하는 검증기가 아닙니다.
- [지도](https://github.com/DietrichGebert/ponytail/blob/9cc65d03aa2da1db7121b912d03596409ee340b8/hooks/ponytail-map.js)는
  Git 파일 목록과 정규식으로 식별자를 모읍니다. 기본 예산은 2,000자이며,
  호출 관계·정확한 타입·실행 경로를 분석하지 않습니다. 지도는 v5.0.0에서 추가됐습니다.
- [하위 에이전트 훅](https://github.com/DietrichGebert/ponytail/blob/9cc65d03aa2da1db7121b912d03596409ee340b8/hooks/ponytail-subagent.js)은
  기본적으로 모든 하위 에이전트에 지침을 넣습니다. 유형 필터는 선택 사항입니다.
- [review](https://github.com/DietrichGebert/ponytail/blob/9cc65d03aa2da1db7121b912d03596409ee340b8/skills/ponytail-review/SKILL.md)는
  구체적인 반례와 연결된 코드를 확인하게 하는 유용한 검토 지침입니다.
  구현 비용 실험을 이 리뷰의 결함 탐지 성능 증거로 사용할 수는 없습니다.
- [gain](https://github.com/DietrichGebert/ponytail/blob/9cc65d03aa2da1db7121b912d03596409ee340b8/skills/ponytail-gain/SKILL.md)은
  공개 벤치마크 표를 보여 주는 명령입니다. 현재 저장소의 절감량을 측정하지 않으며,
  그 수치를 만들어 내지 말라는 제한은 명확합니다.

## 측정 결과를 나누어 읽기

[공식 2026-10-07 보고](https://github.com/DietrichGebert/ponytail/blob/9cc65d03aa2da1db7121b912d03596409ee340b8/benchmarks/results/2026-10-07-agentic.md)는
Opus 5.5·Claude Code, 39종 과제·조건별 5회입니다. 전체 코드 감소는 53%, 비용 감소는
26%로 보고합니다. 에이전트의 Bash 실행은 막았습니다. 숨겨진 실행 검사는 18종에만 있고,
나머지 21종은 품질 검증 결과로 세지 않는다고 명시합니다.

공개 과제별 표의 반올림된 중앙값으로, 과제별 `Ponytail 5 / baseline` 비율의
기하평균을 다시 계산했습니다. 새 모델 실험이나 원시 실행 자료 재분석이 아닙니다.
분류는 보고서의 종류 열을 사용했고, 기준 비용이 timeout인 `vibe-md2html`은 제외했습니다.

| 종류 | 계산에 쓴 과제 수 | 코드 변화 | 비용 변화 |
| --- | ---: | ---: | ---: |
| 숨겨진 검사가 있는 수정 | 18 | -30.2% | -1.0% |
| 기존 저장소의 새 기능 | 12 | -61.7% | -41.9% |
| 작은 앱 작성 | 5 | -76.0% | -52.3% |
| 학습 예제 | 3 | -66.3% | -28.0% |

현재 해석: 선택의 여지가 큰 새 구현에서 이득이 집중됩니다. 실제 업무 비중을 반영한
평균이 아니며, 새 기능군의 동일한 완성도가 검증된 것도 아닙니다.

공식 숨겨진 검사 통과는 기본 86/90, Ponytail 5 87/90입니다. 개인정보 과제는 양쪽 모두
2/5입니다. 테스트 작성 빈도는 증가하지만, 테스트가 존재하는 경우의 변이 탐지는
기본 77%, Ponytail 5 69%입니다. 답변 비교도 무스킬 대비 유의한 우위는 보고하지 않습니다.
테스트를 남기는 빈도, 테스트의 탐지력, 설명 품질은 별개입니다.

[JetBrains 독립 실험](https://blog.jetbrains.com/ai/2026/07/ponytail-skill-claude-tested/)은
4.8.4·Sonnet 5·80개 짝 비교에서 비용 중앙값 -10.3%, 작성 코드 약 -15%를 보고합니다.
코드 수치는 최종 구현 크기가 아닌 누적 작성량이며, 품질 동등성을 입증한 실험은 아닙니다.
비용 절감 방향에 외부 근거가 있다는 의미는 있지만 모든 환경의 절감률은 아닙니다.

## 평가 코드에서 확인한 한계

1. [채점기](https://github.com/DietrichGebert/ponytail/blob/9cc65d03aa2da1db7121b912d03596409ee340b8/benchmarks/agentic/run.py)는
   실제 저장소 과제에서 추가 코드가 있으면 `correct=1`, `safe=1`을 반환합니다.
   합성 Git 저장소에서 `export const DatePicker = null;` 한 줄을 추가한 뒤
   `score_workspace('tmpl-fe-datepicker', ...)`를 호출해 이 결과를 재현했습니다.
   정상 구현과의 모델 비교가 아니라, 채점 함수의 의미를 검증한 단위 재현입니다.
   공식 보고가 이 과제를 품질 결과에서 제외한 것과 일치합니다.
2. [과제 코드](https://github.com/DietrichGebert/ponytail/blob/9cc65d03aa2da1db7121b912d03596409ee340b8/benchmarks/agentic/tasks.py)의
   후보군 주석에는 baseline 대 Ponytail을 먼저 비교해 우세한 후보를 남긴다는 설명이
   있습니다. 전체 39종의 정확한 선별 이력은 공개 자료만으로 확정하지 못했습니다.
   이 과제들로 지침을 반복 개선한 흔적은 있으나 별도의 미사용 평가군은 확인하지 못해,
   새 업무에 대한 일반화보다 개발용 평가로 읽는 편이 타당합니다.
3. 현재 공개 트리에는 해당 실행들의 원시 `results.json`과 변이 검사 도구가 없습니다.
   표는 재계산할 수 있지만 신뢰구간·누락 실행·개별 결과물까지 독립 재검산하지 못했습니다.
   [비교 스크립트](https://github.com/DietrichGebert/ponytail/blob/9cc65d03aa2da1db7121b912d03596409ee340b8/benchmarks/agentic/compare.py)는
   비율의 중앙값을 출력합니다. 보고서의 기하평균·부트스트랩 계산 전체가 이 스크립트로
   재현되는 것은 아닙니다.
4. 최신 비교군은 무스킬·이전 Ponytail·새 Ponytail입니다. 현재 사용자의 작업 규칙이나
   동등한 짧은 지침과의 비교가 없습니다. 과거의 짧은 프롬프트 비교는 다른 모델·버전입니다.
   플러그인 조건에는 코드 지도도 들어갈 수 있어 지침 문구만의 효과로 분리할 수 없습니다.

## 공급자 없이 직접 실행한 검증

macOS에서 임시 복제본을 사용했습니다. 소스와 테스트를 먼저 확인했고, 설치하지 않았습니다.

| 검증 | 실제 결과 | 증명 범위 |
| --- | --- | --- |
| `python3 benchmarks/agentic/run.py --selftest` | 성공 | 18종의 정상·오류 참조 36건과 보조 검사 3건 |
| `npm test` | 상위 127건 중 126 통과, 1 실패 | pandas가 없는 Python 환경에서 CSV 정상 참조 검사 실패. 전체 성공 아님 |
| `npm test --prefix pi-extension` | 별도 실행 28/28 통과 | 앞선 실패 때문에 건너뛴 하위 패키지의 오프라인 테스트 |
| 가짜 날짜 선택기 채점 | `correct=1`, `safe=1`, 1 LOC | 코드 존재 판정을 정확성 판정으로 읽을 수 없음 |
| 격리된 훅 입력 | `ultra → compact → full`, `off → resume → full` | 시작 훅이 저장된 현재 상태 대신 기본 모드로 덮어씀 |
| 추적·미추적 Python 파일의 지도 | 추적된 함수만 표시 | 추적 파일이 있으면 `git ls-files`에 없는 새 파일은 누락 |

모드 재현은 임시 `PLUGIN_DATA`, `CLAUDE_CONFIG_DIR`, `XDG_CONFIG_HOME`과 기본 full을
설정한 뒤 훅에 JSON을 전달한 것입니다. 매니페스트는 resume·compact에도 같은 훅을
연결합니다. 실제 Codex/Claude 세션에서 해당 이벤트가 전달되는 과정까지 실행하지는
않았습니다. [상태 코드](https://github.com/DietrichGebert/ponytail/blob/9cc65d03aa2da1db7121b912d03596409ee340b8/hooks/ponytail-runtime.js)는
같은 저장소의 세션끼리 모드를 공유하는 제한도 명시합니다.

## 대안과 현재 판단

- 전체 플러그인 상시 사용: 반복 주입과 지도는 편리하지만, 현재 작업 규칙 대비 추가
  효과와 호스트 동작은 아직 검증하지 않았습니다.
- 재사용·최소 완결 변경 원칙을 기존 지침에 반영: 작은 추가 비용의 대안이지만,
  Ponytail과 동등한 효과가 있다는 실측은 없습니다. 이번에 지침을 바꾸지 않았습니다.
- 기본 유지: 현재 작업 규칙 위에서 효과가 확인되기 전의 합리적인 선택입니다.

검토자의 권고는 **무조건적인 상시 설치보다, 과잉 구현이 자주 발생하는 작업에 한정해
추가 가치를 비교하자**입니다. 사용자의 설치·유지 결정으로 기록하지 않습니다.
비교한다면 현재 지침, 짧은 추가 원칙, 전체 플러그인을 구분하고, 동일 요구사항 통과와
수정까지 완료한 비용을 먼저 측정해야 합니다. 이것은 제안이며 실행 승인이나 실험 결과가 아닙니다.

## 다음에 쓸 배움

현재 해석: 출력 크기와 제품 완성도, 규칙 준수와 실제 결함 방지, 훅 테스트와 모델 품질을
분리해야 합니다. 스킬은 모델의 구현 선택을 바꿀 수 있지만, 기존 지침 대비 추가 효용이
있다는 결론에는 그 기존 지침을 포함한 비교가 필요합니다. 새 규칙을 제품에 추가하거나
기존 스킬을 삭제할 근거로 이번 검토를 확대하지 않습니다.
