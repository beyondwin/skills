# 두 번의 생성 기회를 실제 납품 품질로 연결할 수 있는가?

결정일·기록일: 2026-10-22. 관련 작업: image-workbench.
근거 성격: 앞선 이미지 품질 비교의 후속 실험. 사용자는 다음 작업을 요청했고,
이전의 실제 Grok 생성·검증·개선 승인 범위에서 진행한다.

## 시작한 문제와 선택

[앞선 비교](2026-10-22-image-quality-comparison.md)에서는 일반 생성과 스킬의
한 장 평균 품질 차이가 사전 기준에 못 미쳤다. 긴 첫 프롬프트는 오히려 악화됐다.
남은 질문은 같은 제한 예산에서 검수와 선택이 실제로 쓸 수 있는 결과를 만드는가다.

첫 프롬프트를 다시 늘리는 대신, 이전에 실행하지 않은 세 과제에서 일반 경로와
현재 2.1.3 스킬을 비교한다. 각 실행은 이미지 도구 최대 두 회를 쓸 수 있다.
첫 결과가 충분하면 멈추고, 필요하면 남은 한 회로 보정하거나 다른 후보를 만든다.
모든 후보를 보존하고 최종 선택 또는 hold를 남겨, 실패한 후보를 숨기지 않는다.

## 실행 전 판정 기준

과제는 여백이 필요한 조명 사진, 세 조약돌이 완전히 보이는 트레이 일러스트,
재질이 중요한 두 유리병 사진이다. 양 경로의 요청·예산·모델·평가 출력은 같고
스킬 설치와 명시적 사용 지시만 다르다. 총 이미지 도구 호출 상한은 12회이며,
거절과 재시도도 포함한다. 기존 비교에는 합산하지 않는다.

별도로 기존 이미지에서 통과·실패 혼합, 전부 실패, 전부 통과인 익명 후보군을
구성한다. 일반 경로와 스킬이 각각 읽기 전용으로 선택하거나 hold하게 하며,
이 검사에는 이미지 생성·수정 권한을 주지 않는다. 이전 판정은 생성 에이전트에게
보여 주지 않는다. 기존 표본의 재검사이므로 새로운 이미지 품질 근거와 구분한다.

실제로 사용할 수 있는 납품은 선택된 파일이 두 독립 평가자의 모든 필수 조건과
화면비 검사를 통과하고, 네 완성도 항목 평균이 4.0/5 이상인 경우로 정한다.
잘못된 수용, 쓸 수 있는 후보를 놓친 hold, 첫 후보와 선택 후보의 차이, 실제 호출
수도 분리한다. 세 과제 각 한 실행으로 통계적 우월성이나 반복 성공률을 주장하지 않는다.

## 결과와 종료 판단

새 이미지 7장을 생성했고, 일반 경로는 세 과제 모두 첫 장으로 사용 가능 기준을
통과했다. 스킬은 조명·유리병 두 과제를 통과했고, 조약돌은 두 장 모두 부족해
보류했다. 스킬의 두 번째 시도는 원래 금지 목록을 프롬프트에서 빠뜨렸고 이미지에
글자가 생겼다. 누락이 글자의 유일한 원인이라고 단정하지는 않는다. 두 평가자는
트레이 형태와 배경 종이가 추가 물체인지에 대해서도 일부 의견이 갈렸다.

기존 후보 선택에서는 일반 2/3, 스킬 1/3이었다. 둘 다 가려진 잎을 수용했고,
스킬은 실제로 보이는 찻상 다리 네 개를 두세 개로 세었다. 원본을 다시 열어
오판을 확인한 뒤, 각 물체의 위치와 경계를 먼저 확인하도록 참고문서만 수정한
개발안을 시험했다. 기존 세 후보군과 별도 두 후보군을 모두 맞춰야 채택한다는
기준을 실행 전에 정했다. 결과는 기존 1/3 그대로, 별도 대조군도 기존·수정안 모두
0/2였다. 추가 지침은 폐기했다.

별도 대조군의 통과 배 후보 하나는 이전 평가에도 줄기 경계가 모호하다고 기록돼
있었다. 해당 두 실행 전에 제외하고 명확한 가림 실패 후보로 바꿨다. 기존 통과
라벨을 실패로 바꾸지는 않았다. 일반 선택 감사가 격리 HOME의 설정을 검색한
읽기 범위 이탈도 별도 기록했다. 정답·이전 점수에 접근한 근거는 없다.

이번 합계는 Grok 세션 11회, 이미지 생성 7회·7장, 읽기 전용 선택 검사 5회다.
실제 모델은 `grok-4.7-build/high`이며 입력·고정 리소스 해시를 유지하고 임시
인증 사본을 삭제했다. 작은 합성 표본과 모델 평가이므로 일반적인 우열, 사람
선호도, 반복 성공률로 해석하지 않는다. 자세한 수치와 조건은
[후속 연구](../../research/2026-10-image-delivery/README.md)에 남겼다.

제품은 런타임 규칙을 더 늘리지 않고, 사용 가이드에 확인된 한계와 운영 전략을
반영한 문서 PATCH 2.1.4로 정리한다. 상세 요청으로 첫 후보를 만들고, 보정할 때
원래 조건을 유지하며, 개수·가림이 중요한 최종본은 독립적으로 직접 확인한다.
스킬은 파일·형식·프로젝트 전달 절차에 쓸 수 있지만 미적 품질 보증으로 권하지 않는다.

검증 기록은 후속 연구에 연결하며, 생성물·평가 원본·실제 호출 기록은 로컬에만
보존한다. 배포·태그·푸시·커밋은 하지 않았다. 자체 검수 오판은 해결됐다고
보고하지 않고 남은 한계로 명시한다.
