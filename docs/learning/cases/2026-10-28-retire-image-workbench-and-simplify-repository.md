# 이미지·동영상 스킬을 종료하고 저장소를 어떻게 줄였는가?

결정일·기록일: 2026-10-28.
관련 작업: image-workbench, grok-image, grok-video 종료, 저장소 구조·문서·검증 구성 정리.
결과: 전체 제품 종료와 저장소 정리 완료. 전체 오프라인 검증과 독립 검토 통과.
근거 성격: 이번 사용자의 직접 요청, 변경 전 저장소 조사, 실제 오프라인 검사.

## 시작한 문제와 당시 조건

사용자는 프로젝트 문서·구조·구성을 다각도로 분석하고 불필요한 부분을 정리하면서
Grok 이미지·동영상 스킬도 정리해 달라고 요청했습니다. 조사 결과 별도 동영상
제품은 로컬 체크아웃에 없었고, image-workbench 하나가 Codex와 Grok 이미지 기능을 함께 지원했습니다.
Grok 부분만 제거하는 선택과 제품 전체를 제거하는 선택을 확인한 뒤, 사용자는
**image-workbench 전체 제거**를 명시했습니다.

변경 전 정식 제품은 세 개였고 작업 트리는 깨끗했습니다. 기존 전체 검증은 통과했지만
문서 링크 검사는 같은 페이지의 존재하지 않는 제목을 무시했습니다. 저장소 도구는
`tomllib` 때문에 Python 3.11 이상이 필요했지만 실행 안내에는 이 조건이 빠져
있었습니다. `docs/history/`에는 안내 파일 하나만 남아 있었습니다.

### 푸시 준비 중 확인한 원격 상태

같은 날 커밋·푸시 요청을 받고 원격을 가져오자, 로컬보다 두 커밋 앞선 원격에
`grok-image`와 `grok-video`가 이미 추가되어 있었습니다. 앞선 "별도 동영상 스킬 없음"
안내는 로컬 범위의 관찰이며 원격 전체에는 맞지 않았습니다. 원격 추가 커밋
`599ad74`와 보호용 ignore 변경 `669edcf`를 반영한 뒤, 처음 요청에 명시된 두 Grok
제품도 함께 제거했습니다. 원격의 연구·학습 기록과 인증·생성물 ignore 규칙은 보존합니다.

## 대안과 선택

- Codex 이미지 기능만 유지하는 대신 사용자가 선택한 전체 제품 종료를 적용했습니다.
- 과거 연구까지 지우는 대신 종료 상태를 표시하고 삭제된 자료는 검증한 Git 리비전으로
  연결했습니다. 과거 결과는 현재 지원 근거나 복원 안내가 아닙니다.
- 빈 문서 분류 폴더를 유지하는 대신 진행 중 판단과 결과를 이 학습 기록의 한 사례에
  이어 적도록 했습니다. 아직 없는 설계 문서를 위한 새 구조는 추가하지 않았습니다.
- 남은 두 스킬의 실행 동작을 다시 설계하지 않고 제품 목록·설치·CI·릴리스·문서 검증의
  실제 불일치를 고쳤습니다. 설치되는 파일은 그대로이므로 남은 제품 버전도 유지합니다.

제품 종료는 사용자의 범위 선택입니다. 기존 이미지 연구의 성패로 이번 이유를
대신하지 않으며, 모든 이미지 워크플로가 불필요하다는 결론으로 확대하지 않습니다.
대체 제품과 재검토 조건은 사용자가 지정하지 않았습니다.

## 구현 방법

`skills/image-workbench/`, 전용 테스트와 관리 문서를 삭제하고 `products.toml`,
제품별 검증 단계, 릴리스 분기, CI 경로와 공개 문서의 현재 목록을 두 제품으로
맞췄습니다. 별칭이나 호환 경로를 남기지 않습니다.
원격에서 확인한 `grok-image`·`grok-video`의 배포 파일·테스트·관리 문서와
`docs/users/en/grok-video-piece.md`, 한국어 가이드도 같은 범위로 제거했습니다.

삭제한 저장소 경로를 직접 가리키던 `~/.agents/skills/image-workbench`와
`~/.claude/skills/image-workbench`의 심볼릭 링크도 대상을 확인한 후 제거했습니다.
별도 복사본이나 다른 스킬·호스트 설정은 수정하지 않았습니다.

문서 검사는 같은 페이지의 제목 앵커와 URL 인코딩된 로컬 경로·앵커를 확인하도록
보완했습니다. 루트 작업 규칙·기여·보안·행동 강령과 연구 색인의 링크도 검사합니다.
과거 연구 전체를 현재 제품 계약으로 취급하지는 않습니다.

저장소 명령에는 Python 3.11 이상 조건을 안내하고 이전 Python에서는 import 오류
대신 필요한 버전을 알리도록 했습니다. 설치된 스킬의 호스트 지원을 넓힌 것은 아닙니다.

한국어 교정의 공개 검증 안내에 남아 있던 35개 표기도 실제 37개로 고쳤습니다.
문서 검사는 숫자를 별도로 고정하는 대신 fixture JSON의 전체·범주별 수량과 대조합니다.
`CLAUDE.md`의 특정 모델 목록과 설치 링크 단정은 실제 설정·실행 기록을 확인하는
안내로 바꿨습니다.

삭제 직전 리비전 `6564ed5f039f3a7c1b1729d0652cc8015ab80f2d`의
[제품 원문](https://github.com/beyondwin/skills/blob/6564ed5f039f3a7c1b1729d0652cc8015ab80f2d/skills/image-workbench/SKILL.md)과
[제품 계약](https://github.com/beyondwin/skills/blob/6564ed5f039f3a7c1b1729d0652cc8015ab80f2d/docs/maintainers/products/image-workbench/contract.md)은
Git 이력으로 확인할 수 있습니다. 이 스냅샷은 이전 모든 실험에서 같은 파일이
실행됐다는 증거가 아닙니다.

## 확인한 결과와 한계

- 변경 전 `python3 scripts/verify.py` 전체 통과.
- 같은 페이지의 잘못된 앵커와 인코딩된 파일 경로 회귀 검사 두 개가 변경 전 실패하고
  수정 후 통과했습니다. 제품 패키지 거부 검사와 함께 13개 검사를 통과했습니다.
- 최종 `python3 scripts/verify.py` 전체 통과: 저장소 246개, 한국어 패키지 11개,
  라이브 러너의 오프라인 단위 검사 256개, how-it-works 64개. 한국어 오프라인 사례
  37개와 mutation 검사, 호출 없는 dry-run, Python 컴파일도 통과했습니다.
- 원격 동기화 전 활성 문서 61개의 로컬 파일 링크·제목 앵커 오류 0건. 이미지 연구 README 7개도
  별도 링크 검사 통과. `git diff --check` 통과.
- 원격 통합 후 같은 전체 검증을 다시 실행해 위 검사 수량으로 모두 통과했습니다.
  원격에서 추가된 학습 사례를 포함한 활성 문서 66개의 링크 오류도 0건입니다.
  두 Grok 제품의 표준 설치 경로에도 디렉터리나 링크가 없음을 확인했습니다.
- 독립 문서·코드 검토에서 차단 결함 없음. 남은 두 제품의 배포 파일 diff는 없습니다.
- macOS 기본 Python 3.9에서 저장소 CLI의 요구 버전 안내를 확인했습니다.
  이 결과는 Python 3.9로 저장소 검증을 지원한다는 뜻이 아닙니다.
- `.agents`, `.codex`, `.claude`, `.grok`의 표준 skill 경로에서 image-workbench
  디렉터리나 링크가 남아 있지 않음을 확인했습니다.

실시간 모델·이미지 호출은 하지 않았습니다. 오프라인 검사는 실제 모델 품질이나
호스트에서의 스킬 실행을 입증하지 않습니다. 종료 제품에 직접 연결된 두 링크 외의
전역 설치·설정, 비공개 실행 자료, 인증 파일은 수정하지 않았습니다.
초기 정리는 로컬에서 완료했으며, 같은 날 사용자의 후속 요청으로 커밋·푸시까지
범위를 넓혔습니다. 릴리스 배포는 요청 범위에 포함하지 않았습니다.

## 유지와 종료 판단

정식 제품은 korean-writing-editor와 how-it-works입니다. 이미지 연구와 학습 사례는
당시 판단의 근거로 보존합니다. 향후 제품 종료 시에는 배포 파일뿐 아니라 설치 안내,
검증 단계, 릴리스 코드와 삭제된 자료를 가리키는 링크도 함께 확인합니다.
