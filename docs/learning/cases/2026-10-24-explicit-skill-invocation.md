# 스킬을 직접 호출할 때만 쓰도록 할까?

결정일·기록일: 2026-10-24.
관련 작업: 정식 스킬 세 개의 활성화 정책.
근거 성격: 사용자의 직접 호출 전용 요청과 저장소 계약. 실제 모델 동작은 미측정.

## 시작한 문제와 선택

사용자가 세 스킬 모두 직접 호출할 때만 사용하도록 요청했습니다.
기존 자동 선택 유지와 설명문만 수정하는 대안 대신, 호스트 설정과 본문을 함께
변경했습니다. 요청 내용으로 자동 선택되는 편의는 포기하고 사용자의 선택을 우선합니다.
과거 [기본 설명 방식 결정](2026-09-12-explain-before-depth-question.md)은 호출 후
설명 방식의 근거이며 자동 호출 유지의 근거로 사용하지 않았습니다.

## 구현 방법

Codex의 `allow_implicit_invocation`을 false로 바꾸고 세 스킬의 설명과 본문에
직접 호출 조건을 반영했습니다. Claude Code를 지원하는 how-it-works에는
`disable-model-invocation: true`를 추가했습니다. Grok은 설명과 본문 규칙에
의존하며 별도 호스트 설정을 검증했다고 주장하지 않습니다.

[버전 규칙](../../maintainers/repository/versioning.md)에 따라 활성화 계약 변경을
메이저 변경으로 기록했습니다. 제품 설명서, 계약, 테스트와 버전 핀도 수정했습니다.
과거 실험 기록은 현재 정책의 증거로 취급하지 않습니다.

## 확인한 결과와 한계

독립 임시 체크아웃에서 `python3 scripts/verify.py` 전체 검증을 통과했습니다.
추가로 현재 작업 트리의 how-it-works와 image-workbench 개별 검증 및
`git diff --check`를 통과했습니다. 직접 호출 설정·패키지·합성 사례를 검사한 결과이며
실제 호스트 호출이나 모델 품질의 증거는 아닙니다.
전역 설치 갱신과 릴리스 배포는 하지 않았습니다.

## 유지 판단

직접 호출 전용 정책을 유지합니다. 자동 선택 복원은 별도 사용자 요청이 있을 때
검토합니다. 설정 검증과 실제 호스트 실행 증거를 구분해야 합니다.
