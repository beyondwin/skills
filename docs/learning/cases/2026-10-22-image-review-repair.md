# 이미지 조건 보존과 개수·가림 검수를 실제로 고칠 수 있는가?

결정 시작일: 2026-10-22. 기록 갱신일: 2026-10-23. 관련 제품: image-workbench.
상태: 실험 종료. 조건 보존만 2.1.5에 반영; 전체 검수 개선 기준은 실패.

## 요청과 출발점

사용자는 [앞선 실험](2026-10-22-image-delivery-budget.md)에서 남긴 개수·가림
오판과 보정 중 조건 누락을 고치고, 같은 조건에서 효과를 다시 확인하도록 요청했다.
문서에 한계를 적는 데서 끝내지 않고 실제 런타임과 검증 경로를 개선한다.

현재 기준판은 2.1.4다. 이전의 공간 목록 추가 규칙은 효과가 없어 폐기됐다.
이번에는 원래 그리기 요청을 고정해 보정 지시만 덧붙이고, 전체 이미지와 실제
부분 상세 이미지를 함께 보게 한다. 상세 보기는 원본 픽셀과 경계를 확인하는
수단이며 개수나 가림을 판정하는 자동 알고리즘으로 취급하지 않는다.

## 선택과 대안

문구를 더 강하게 반복하는 대안은 이전 실패 때문에 선택하지 않았다. 상세
보기가 필요할 때만 기본 뷰어를 쓰고, 그것이 불가능하면 원본을 변경하지 않는
임시 검수용 crop을 쓰는 방식을 시험한다. 감사 모드의 기본 읽기 전용 계약은
유지하며, 감사 실험에서는 양쪽 모두에 임시 진단 파일 권한을 명시한다.

원문 보존은 실제 이미지 도구에 전달된 프롬프트로 확인한다. 조건이 전달된
것과 출력 이미지가 조건을 충족한 것은 다른 결과다. 상세 보기도 실제 도구
기록이 있을 때만 실행됐다고 인정한다.

## 실행 전 기준

- 기존 실패 이미지에서 개수·가림 오판을 분리해 비교한다. 같은 입력·권한·시간
  한도로 기준판과 개선안을 실행한다. 과거 감사와 임시 crop 권한이 다름을 기록한다.
- 별도 보정 실험에서 원문의 주제·개수·윤곽·구도·재질·빛·금지 조건·화면비가
  실제 보정 호출에 모두 남아 있어야 한다. 원문 누락은 0건이어야 한다.
- 앞선 조명·조약돌·유리병 요청은 바꾸지 않는다. 일반·기준판·개선판을 현재
  CLI에서 각각 실행하고, 각 요청의 이미지 호출 상한은 두 번으로 유지한다.
- 결과물은 방법을 숨긴 두 평가자가 모든 후보를 평가한다. 원래 필수 조건과
  화면비를 모두 통과하고 완성도 평균이 4.0/5 이상일 때만 사용 가능으로 센다.
- 개발에 쓰지 않은 새 결과로 판정 능력을 다시 확인한다. 불명확한 경계는
  성공으로 바꾸지 않는다. 평가가 끝난 표본에 맞춰 다시 수정하면 개발 근거로
  만 남기고 독립 검증이라고 부르지 않는다.

CLI가 이전 1.0.62에서 1.0.67로 바뀌었으므로 과거 숫자만으로 개선 효과를
계산하지 않는다. 현재 실행 파일과 스킬 전체 리소스를 고정한다. 개선 문구와
도구를 채택할지는 실제 결과로 결정하며, 작은 합성 표본으로 미적 우월성이나
일반 성공률을 주장하지 않는다.

## 결과

첫 개선안 A는 개수·가림 판정을 개선하지 못했다. 기준판과 A 모두 10장 중
5장을 맞혔고, 5개 묶음에서 올바른 선택은 1개였다. 잘못 통과시킨 이미지가
각 2장, 잘못 탈락시킨 이미지가 각 3장이었다. A가 만든 30개 상세 이미지는
실제로 모두 열렸고, 전달된 원본 10개와 상세 30개의 이미지 바이트도 원본과
일치했다. 따라서 상세 이미지가 전달되지 않은 문제로 설명하지 않는다.

별도 보정 비교에서는 A의 실제 이미지 호출이 원래 그리기 요청을 그대로
보존했다. 기준판은 금지 조건 문장 전체를 빠뜨렸고 출력에 글자가 생겼다.
A는 금지 조건을 유지했고 글자 없는 결과를 만들었다. 각각 한 번 생성한
결과이며 조건 전달과 이미지 충족을 별도로 판정한다.

다음 개선안 B는 한 이미지의 검수를 끝낸 뒤 다음 이미지를 열게 하고,
상세 파일 이름에 출처를 남긴다. 발은 별도 장식이 아닌 바닥 접점으로 보고,
완전한 윤곽이 필요한 물체가 앞쪽 테두리에서 끊기는지 확인한다. 이 변경들은
묶어서 평가하며 개별 기여를 주장하지 않는다.

B는 원본 10장 중 8장, 만든 상세 이미지 18개 중 16개를 연 상태에서 30턴
한도에 걸렸다. 394.802초 후 종료됐고 최종 보고서가 없어 정확도는 미측정이다.
한도를 늘리거나 같은 실행을 이어서 성공으로 바꾸지 않는다. 잠정 판단에도
기존 오판이 남아 있어 순서 변경만으로 해결됐다고 해석하지 않는다.

마지막 개발안 C는 작은 비교 묶음 안에서 독립 호출을 묶고, 필요한 물체와
접점이 함께 보이는 상세 이미지 한 개를 사용한다. 이미 분명한 여백이나 실패를
반복 확대하지 않고 결과 보고까지 기존 예산으로 마치도록 줄였다. 완주 여부와
정확도를 따로 확인했다. C는 23턴·669.508초에 정상 종료했지만 10장 중 4장만
맞혔고, 잘못 통과시킨 이미지가 3장으로 늘었다. 예산 내 완주는 회복했으나
시각 판정은 나빠져 폐기했다. 정확한 확대 파일 생성과 원본 보존을 확인한
도구 검사 18개도 모델의 시각 판정 개선을 증명하지 못하므로 제품에 넣지 않는다.

채택할 2.1.5에는 원문 조건 보존과 보정 후 전체 필수 조건 재검사만 남긴다.
원문 보존 비교를 본 두 익명 평가자는 개선 이미지를 모두 통과시켰고 완성도는
4.0/5였다. 기존 이미지는 두 평가자가 모두 문자를 확인해 탈락했고 완성도는
3.25/5였다. 매끈함 조건에는 평가자 불일치가 남았다. 한 쌍의 개발 비교이며
일반 우위를 뜻하지 않는다. 앞선 탐색 평가에는 경로에 방법 이름이 드러나
익명 집계에서 제외하고 별도 기록으로 남겼다.

실패한 시각 규칙을 더 붙이지 않는 결정과 최종 후보를 고정한 뒤 같은 세
요청·호출 예산으로 일반 생성, 2.1.4, 2.1.5를 재시험한다. 개수·가림 오판은
미해결로 명시하고, 새 이미지에서 결과가 좋아도 과거 실패를 지우지 않는다.

최종 새 생성은 9회 실행, 12회 이미지 호출로 정상 완료했다. 두 익명 평가자가
원본 12장을 모두 판정했다. 사용 가능 전달은 일반 2/3, 기존판 3/3, 개선판
3/3이고, 선택본 완성도는 3.83·4.00·4.00/5였다. 개선판은 기존판과 품질이
같으면서 이미지 호출을 3회 대신 5회 썼다. 유리병의 각인 흔적은 보정으로
없어졌지만, 조약돌은 이미 통과한 후보를 다시 만들어 완성도가 그대로였다.
추가 호출 자체를 품질 개선으로 세지 않는다.

개선판의 실제 보정 2회 모두 최초 그리기 프롬프트 전체를 그대로 앞에 두고
변경 사항을 덧붙였으며, 원래 시각 조건 7범주와 화면비를 유지했다. 다만 첫
프롬프트의 도입부가 압축되고 운영 문구가 빠져 원래 사용자 문장의 완전한
축자 보존까지 확인된 것은 아니다. 기존판은 최종 비교에서 보정을 하지 않아
그 비교의 보정 분모가 0이다. 일반 생성은 처음부터 빠진 글자·로고·워터마크
금지를 보정에서도 생략했으며, 보정 중 새로 잃은 조건으로 집계하지 않는다.

관찰된 이득은 특정 조건 누락을 막는 절차다. 세 요청에서 미적 우월성이나
비용 개선은 확인되지 않았다. 숫자와 분모, 실패한 대안은
[실험 기록](../../research/2026-10-image-review-repair/README.md)에 함께 남긴다.

새 이미지 12장 전부를 다시 익명으로 제시한 선택 검증에서는 기존판이 10장,
개선판이 9장을 정확히 판정했다. 두 버전 모두 실패 후보 2장은 거절했고
3개 묶음에서 통과 후보를 골랐지만, 정상 후보를 잘못 탈락시킨 수가 2장에서
3장으로 늘어 비퇴행 기준을 통과하지 못했다. 개선판은 배경 종이 두 개와
램프에 붙은 받침을 별도 물체로 해석했다. 새 표본에는 가림 실패나 모든 후보가
실패한 묶음이 없으므로 그 능력을 확인한 결과로 확대하지 않는다.

두 실행의 원본·설치본·이미지 전달 바이트·호출 예산은 보존됐다. 기존판은
JSON만 허용된 임시 기록을 평문 9개로 남겨 엄격한 절차 검증에서 실패했다.
개선판도 임시 JPEG 29개에 PNG 확장자를 붙이고 기록에는 PNG로 재인코딩했다고
잘못 적은 결함이 있었다. PNG 인코딩은 필수가 아닌 허용 옵션이었다. 원본이나
납품물을 바꾸지는 않았으며, 시각 점수와 절차 이탈을 따로 기록했다.

## 유지와 종료 판단

전체 검수 절차를 고쳤다는 목표는 달성하지 못했다. 실행 전 정한 유효한 일부
변경만 남기는 기준에 따라 조건 보존 수정을 유지하며, 검수의 비퇴행 실패를
사용자 안내와 CHANGELOG에도 명시한다. 실패한 확대 도구나 시각 규칙은
제품에 넣지 않는다. 보정 결과가 좋아진 근거와 전체 목표 실패를 함께 남긴다.

실용 전략은 상세한 원래 조건을 고정하고, 한 번 만든 뒤 눈에 보이는 실패만
표적으로 보정하며, 모든 원래 조건을 다시 확인하는 것이다. 이미 통과했다면
추가 생성으로 품질이 좋아진다고 가정하지 않는다. 개수나 전체 윤곽이 중요하면
별도 검수자가 실제 이미지를 확인해야 한다. 지시나 확대를 더 붙이는 것만으로
개수·가림 오판이 해결된다는 가설은 이번 결과가 뒷받침하지 않는다.

제품 범위 검사 32개 사례·17개 변이·65개 단위 테스트와 작업 파일 스냅샷의
전체 단위 테스트 642개를 통과했다. 실험 핀·검증 스냅샷·현재 런타임 7개 파일의
해시도 일치했다. 원본 링크와 평가 상세 표시, 1280px·390px 브라우저 화면을
직접 확인했다. 이 검증들은 이미지 품질이나 사람의 선호를 대신하지 않는다.
