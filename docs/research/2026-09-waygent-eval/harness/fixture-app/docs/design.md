# 사용량 화면 설계서

## 1. 배경

운영자는 콘솔에서 모델 호출 목록과 모델별 비용을 봅니다. 비용 숫자는 매달 청구서와 맞춰
보는 데 쓰입니다. 서버는 수집기가 남긴 호출 기록을 읽어 API로 내주고, 콘솔은 그 API만
부릅니다. 서버, API 계약, 콘솔, 콘솔 시험용 목(mock)은 한 저장소에 있고 함께 바뀝니다.

## 2. 호출 기록

수집기는 호출 시도마다 한 줄을 남깁니다. 실패한 시도(429, 5xx, 시간 초과)는 제공사가 토큰
수를 주지 않으므로, 수집기가 예약해 둔 최대치를 토큰 수로 적고 `estimated`를 켭니다. 이
숫자는 실제로 쓴 토큰이 아닙니다. 제공사가 토큰 수를 준 실패(`estimated`가 꺼진 실패)는
실제로 청구됩니다.

옛 수집기 형식 때문에 저장 데이터는 "차단 없음"을 빈 문자열(`""`)로 적습니다.

## 3. API 계약

- 시각은 ISO 8601, 시간대 포함.
- `blocked_by`: 호출을 막은 정책 id, 막지 않았으면 `null`. 빈 문자열은 계약에 없습니다.
- 돈은 소수점 여섯째 자리까지 문자열로(`"0.012345"`). 반올림은 ROUND_HALF_UP, 모두 더한 뒤
  한 번만 합니다.
- 오류는 `{"error": "<code>"}`와 알맞은 상태 코드.

콘솔 목은 실제 서버 응답과 모양이 같아야 합니다. 목만 통과하고 실제 서버와는 어긋나는
콘솔은 지난 분기에 두 번 운영 장애를 냈습니다.

## 4. 비용

모델별 비용은 실제로 청구되는 토큰만 셉니다. 시도 수는 실패를 포함한 모든 시도를 셉니다.
지난달 콘솔이 추정치까지 비용에 넣어, 429가 몰린 날 비용이 청구서의 세 배로 보였습니다.

## 5. 차단 표시

호출 목록에서 차단된 호출 줄 끝에 `차단 <정책 id>`를 붙입니다. 차단되지 않은 호출에는
아무것도 붙이지 않습니다.

## 6. 호출자 허용 목록

서버는 허용된 호출자만 받습니다. 요청의 `X-Caller` 헤더가 설정의 `allowed_callers`에
없으면 403 `{"error": "caller_not_allowed"}`. 콘솔은 자기 이름 `console`을 `X-Caller`로
보냅니다.

`allowed_callers`는 필수 설정입니다. 없으면 서버는 기동하지 않고(`ConfigError`) 뜨지 않은
이유를 알립니다. 조용히 모두 허용하거나 모두 막는 기본값은 두지 않습니다.

## 7. 운영

운영 설정은 `config/prod.toml`이고, 배포는 이 파일 값으로 뜹니다. 운영에서도 콘솔은 이
서버를 불러야 합니다. 배포 순서는 설정 → 서버 → 콘솔입니다.
