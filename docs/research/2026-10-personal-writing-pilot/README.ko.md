# 개인용 한국어 기술 글쓰기 시험판

2026-10-09. [English](README.md).

[앞선 실험](../2026-10-ko-clear-writing-eval/README.ko.md)을 바탕으로 개인용
Codex 스킬을 만들고 실제 파일 읽기·작성 흐름을 확인하는 후속 작업입니다.
0.1.0 후보가 정한 인수 기준을 통과해 `~/.codex/skills/ko-technical-writing`에
설치했습니다. 설치 파일 6개가 평가한 해시와 일치합니다. 새 Codex 대화에서 사용할
수 있습니다. 현재 데스크톱 대화에서 설치 후 자동 선택까지 확인한 것은 아닙니다.

## 만든 것

`ko-technical-writing`은 근거를 읽어 기술 문서, 운영 절차, 커밋 메시지, PR 설명,
인계문을 작성합니다. 짧은 진입 지침과 작업별 참조 두 개로 구성합니다.
별도 모델이나 린터를 호출하지 않습니다. 원문 교정은 기존 교정기의 역할로 둡니다.

특히 다음 구분을 지킵니다.

- 자료에 없음 / 확인 여부를 모름 / 실제 실행하지 않음
- 스테이징된 변경 / 아직 스테이징하지 않은 변경
- PR의 커밋 범위 / 로컬 작업 중인 변경
- 과거 버전의 테스트 통과 / 현재 변경의 검증

ASD-STE100의 영어 어휘나 단어 수 제한을 강제하지 않으며 표준 준수를 주장하지
않습니다. 저장소 제품 목록과 전역 지침을 바꾸지 않는 개인용 시험판입니다.

## 검증 방법

새 합성 과제 8개를 일반 실행과 비교하고, 교정·번역·일상 대화·코드 리뷰의 오작동
여부를 별도 4개 과제로 확인합니다. 총 20회이며 수정 확인용 4회를 포함한 상한은
24회입니다. 각 실행은 다른 HOME/CODEX_HOME과 합성 Git 저장소를 사용합니다.
메모리와 슈퍼파워스 없이 실제 스킬 자동 선택, 참조 읽기, 자료 조회를 관찰합니다.

스테이징·미스테이징 혼합, PR 범위 밖 변경, Git 설정에 가려진 서브모듈 변경도
포함합니다. 후보·과제·판정 기준의 해시는 모델 실행 전에 고정했습니다.
작성자가 모든 출력의 의미와 범위를 검토하며 JSON과 파일 보존은 코드로 검사합니다.
독립 채점이나 사람의 이해도 실험은 아닙니다.

설치 기준은 후보의 의미·범위·형식과 선택·읽기 기준을 모두 통과하는 것입니다.
기본 실행도 통과하면 더 좋은 품질이라고 주장하지 않습니다.

## 실제 결과

21회 시도해 답변 20개를 확보했습니다. 첫 일상 대화 과제는 서버의 HTTP 503·모델
용량 부족으로 생성되지 않았습니다. 같은 입력과 후보로 한 번 재시도했고 성공했습니다.
실패 기록은 그대로 남겼으며 후보 지침은 실험 전후 바꾸지 않았습니다.

완료된 실행은 모두 Codex CLI 0.160.1의 `gpt-6-astra` / `high`였습니다.
실제 rollout의 실행 정보를 확인했습니다.

| 항목 | 일반 실행 | 개인용 스킬 |
| --- | ---: | ---: |
| 의미·범위·형식 기준 통과 | 8/8 | 8/8 |
| 진입 지침과 필요한 참조 실제 읽기 | 해당 없음 | 8/8 |
| 제외 대상에서 잘못 선택 | 미측정 | 0/4 |
| 작성 과제 실행 시간 중앙값 | 26.26초 | 23.47초 |
| 답변 총 글자 수 | 1,836자 | 2,179자 |
| 보고된 입력 토큰 | 213,336 | 301,675 |
| 그중 캐시 입력 토큰 | 106,112 | 187,776 |
| 보고된 출력 토큰 | 1,775 | 3,367 |

두 JSON 답변은 지정된 키와 `null`·`false`를 보존했습니다. 21개 실행 모두 파일·
스테이징 영역·HEAD가 유지됐습니다. 교정 요청에는 기존 교정기가 선택됐습니다.

**일반 실행보다 품질이 좋아졌다는 증거는 없습니다.** 일반 실행도 숨겨진 서브모듈
변경과 검증 근거의 공백을 올바르게 처리했습니다. 스킬은 더 많은 토큰을 사용했고
답변도 길었습니다. 시간은 단회·동시 실행·캐시의 영향을 받으므로 더 빠르다는 근거로
사용하지 않습니다. 사용량은 도구 호출 과정까지 포함하며 청구 금액은 아닙니다.

이번 채택 이유는 요청한 개인용 작성 흐름을 반복해서 쓸 수 있는 형태로 갖추었고,
정한 의미·선택 기준에서 결함을 관측하지 않았기 때문입니다. 모든 답변에 필수로
적용할 이유는 없습니다. 사람의 이해도, 다른 모델·호스트, 장기간 사용 가치는
미측정이며 실제 사용 부담이 크면 더 줄이거나 제거할 수 있습니다.

## 검증에서 발견한 기록상의 주의점

한 일반 실행의 CLI 요약 이벤트에는 마지막 실패한 복합 명령이 빠졌지만, 전체
rollout에는 서브모듈 diff를 읽은 결과가 있었습니다. 모든 실행의 전체 도구 호출을
확인한 후 판정했습니다. 요약 이벤트 개수만으로 자료를 읽지 않았다고 단정하지
않습니다. 해당 명령 뒤쪽의 하위 저장소 조회는 초기화하지 않은 합성 gitlink여서
실패했으며, 앞서 확보한 diff까지 무효가 되는 것은 아닙니다.

정적 검사와 macOS Python 3.9.6 실행을 확인했습니다. 최종 문서·집계 검사는
[검증 기록](verification.md)에 있습니다. 이 실험은 읽기 전용 환경에서 초안 작성과
근거 조회를 검증했으며 실제 파일 저장, 모든 개인 플러그인과의 공존, 쓰기 권한
환경에서의 권한 준수까지 입증하지 않습니다.
