# 한국어 기술 글쓰기: 읽기 품질 개선

[English](README.md)

목표는 독자가 기술 설명을 한 번 읽고 원인과 조건, 다음 행동을 이해하도록 돕는
개인용 스킬입니다. [앞선 실험](../2026-10-personal-writing-pilot/README.ko.md)은
근거 보존과 실제 스킬 사용을 확인했으며 사람의 이해도를 측정하지 않았습니다.
기존 0.1.0과 결과를 동결한 상태로 두고 이 폴더에서 0.2.0을 따로 평가합니다.

## 실행 전에 정한 방법

[프로토콜](protocol.json)은 두 버전의 전체 파일, 합성 과제, 실행 코드의 해시와
채택 조건을 고정합니다. [과제](cases.json)는 직접 만든 메모·요청·이해 질문으로
구성합니다. 작성 모델에는 메모와 요청만 제공하며 질문과 정답은 보여주지 않습니다.
과제마다 일반 실행, 0.1.0, 0.2.0으로 작성합니다. 모든 실행은 메모리를 끈 별도
Codex 홈과 읽기 전용 작업 폴더를 사용합니다. 기존 한국어 교정기는 함께 설치하지만
슈퍼파워스는 설치하지 않습니다.

새 지침은 독자가 궁금해할 순서, 인과관계, 구체적인 한국어 동사, 명확한 지시어,
반복을 고치는 편집에 집중합니다. 문장 길이를 점수로 삼거나 제목을 금지하지 않습니다.
일상 사용에서 추가 모델 서비스도 필요하지 않습니다. 저장소의 세 지원 제품과
별개인 개인용 스킬로 유지합니다.

각 과제는 버전을 가린 A/B/C 문서를 두 번 평가하며 두 번째에는 순서를 뒤집습니다.
평가 모델은 원문과 요청을 보지만 스킬 지침·버전 이름·채택 기준은 보지 않습니다.
핵심 파악, 관계 이해, 자연스러움, 군더더기를 사실 정확성과 분리해 채점합니다.
이때의 이해 질문 응답은 원문을 본 평가이므로 독자 이해도 결과로 쓰지 않습니다.
별도로 두 과제의 두 버전에서 원문 없이 문서만 읽는 모델이 질문 세 개에 답합니다.
이는 답을 찾을 수 있는지 보는 보조 검사이며 사람의 읽기 속도 측정이 아닙니다.

설치에는 미리 정한 절대 품질·회귀 조건을 사용합니다. 비교 우위를 주장하는 조건은
별도로 더 엄격하게 둡니다. 어느 조건을 통과해도 일반적인 성능 향상이나 사람의
이해도 향상이 입증됐다고 해석하지 않습니다.

## 재현과 비공개 자료

기본 명령은 실제 모델을 호출하지 않습니다.

```sh
python3 docs/research/2026-10-writing-readability/study.py generate /path/outside/git
```

사용자가 허용한 범위에서만 `--execute --auth /path/to/auth.json`을 추가합니다.
`generate`, `judge`, `regression`, `reader` 순서로 진행합니다. 설치 전 조건을
통과한 후보를 설치한 뒤 `smoke`를 실행합니다. 모든 단계가 호출 기록을 공유하고
실패를 포함해 40회를 넘지 않습니다. 같은 ID를 다시 실행할 수 없으며 통신 재시도는
새 ID와 동일 입력을 사용해야 합니다. 실제 모델·추론 수준은 실행 기록에서 읽습니다.
각 실행의 인증 복사본은 실행이 끝나면 삭제합니다.

```sh
python3 docs/research/2026-10-writing-readability/summarize.py /path/outside/git --out /tmp/results.json
```

집계기는 해시, 호출 중복, 인증 파일 정리, 설치 파일, 평가 응답 형식을 확인합니다.
요약 이벤트가 실패한 복합 명령을 누락할 수 있으므로 전체 실행 기록도 확인합니다.
원본 프롬프트·모델 출력·실행 기록은 Git 밖에 보관합니다. 저장소에는 합성 입력과
집계·해시·판단 근거만 남깁니다.

## 원칙의 출처와 한계

[ASD 공식 설명](https://www.asd-ste100.org/about.html)은 기술 지시를 이해하기
쉽게 만드는 목적과 용어 일관성을 설명합니다. [공식 FAQ](https://asd-ste100.org/STE_faq.html)는
절차 설명과 기술 서술을 일반적인 글과 구분합니다. 한국어에 맞게 원칙을 응용하되
영어 사전·단어 수 제한을 복제하거나 ASD-STE100 준수를 주장하지 않습니다.
독자 중심 편집 과정은 우리가 검증할 설계이며 공식 표준의 한국어 규칙이 아닙니다.

작성과 평가가 같은 모델 계열이므로 버전을 가려도 취향이 겹칠 수 있습니다.
의미 대조는 작성자도 수행합니다. 순서 교환은 위치 편향을 확인할 뿐 사람의 독립적인
동의를 뜻하지 않습니다. 합성 과제 여섯 개로 사람의 읽기 시간, 장기 효용, 다른
호스트 지원까지 입증할 수 없습니다.

## 보정과 추가 모델

[블라인드 보정](masking-amendment.json): 첫 평가 호출 전에 파일 링크에서 버전 이름이
드러나는 문제를 발견했습니다. `masked_evaluation.py judge`와 `reader`는 작업 폴더
경로만 `/source/`로 바꿉니다. 내용과 채점 기준은 유지하며 두 해시는 별도 기록합니다.
두 단계는 원래 실행기 대신 이 보정 실행기를 사용합니다.

[통신 재시도 기록](followup.json)은 서버 용량 오류와 동일 입력 재시도를 보존합니다.
답변이 없는 실행을 의미 오류로 세지 않습니다.

사용자는 이어서 Claude CLI Opus와 Cursor Agent Grok도 요청했습니다.
[추가 프로토콜](external-protocol.json)은 각 모델의 일반 실행·후보 여섯 쌍,
서로 다른 제공자의 블라인드 평가, 채점기 대조 검사를 추가 40회 안에서 수행합니다.
`external.py generate`로 Opus와 Grok High의 첫 과제를 실행했습니다. High가 제한
시간을 넘겨 [후속 조건](external-followup.json)에서 Grok Medium의 두 조건을 모두
새로 시작합니다. `external_followup.py generate-medium`, `judge`, `control`을
사용합니다. 각 명령은 Git 밖의 출력 경로를 받으며 실제 호출에는 `--execute`가
필요합니다. `external_summary.py`로 집계를 재현합니다. High와 Medium은 섞지 않습니다.

추가 CLI 실험에서는 스킬과 문서용 참조를 입력에 넣고 도구와 자동 스킬 선택을
차단합니다. 글쓰기 지침의 행동을 확인하며 Claude/Cursor의 설치·자동 선택·파일
읽기 지원까지 검증하는 실험은 아닙니다. Opus가 Grok의 결과를, Grok이 Opus의 결과를
평가합니다. 대조 검사는 잘못된 완료 주장과 심한 반복을 넣습니다. 이를 잡아도
미묘한 문체 차이까지 잘 판별한다는 뜻은 아닙니다.

## Codex 0.2.0 비교 결과

[집계](results.json): 40회 호출 중 37개 답변이 완성됐고 모든 작업 폴더가 유지됐습니다.
세 번은 답변 전에 서버 용량 오류(503)로 끝났습니다. 캐시 평가와 스테이징 커밋은
같은 입력으로 재시도했고, 이전 버전의 페이지네이션 독자 검사는 답변이 없습니다.
미완료를 의미 오류로 세지 않습니다. 실제 실행은 Codex CLI 0.160.1의 gpt-6-astra/high입니다.

작성자 대조에서 후보 여섯 개는 판단에 필요한 의미를 보존했습니다. 블라인드 평가
12개는 후보의 네 항목에 모두 4/4를 줬지만, 이전 버전도 모든 선호 집합에 함께 들어갔습니다.
따라서 선호 개선은 확인하지 못했습니다. 한 평가의 일반 실행 경로 오류 지적은 익명
경로 보정이 만든 오탐이며 [작성자 판정](author-grades.json)에 따로 기록했습니다.
높은 점수가 상한에 몰린 결과를 사람의 읽기 품질 증거로 쓰지 않습니다.

기존 작업 흐름 네 개는 커밋 재시도 후 모두 통과했습니다. 원문 없는 독자 모델은
후보 질문 6/6에 맞게 답했습니다. 이전 버전은 3/3 정답이고 나머지 3문항은 응답이 없습니다.
답을 찾을 수 있다는 확인이며 사람의 읽기 속도 검사가 아닙니다.

| 작성 과제 여섯 개 | 일반 실행 | 0.1.0 | 0.2.0 |
|---|---:|---:|---:|
| 최종 답변 글자 수 합계 | 10097 | 10511 | 10774 |
| 소요 시간 중앙값(초) | 41.290 | 44.346 | 47.238 |
| 보고된 입력 토큰 합계 | 124726 | 206027 | 210240 |
| 보고된 출력 토큰 합계 | 6465 | 7220 | 7426 |

토큰은 도구 실행을 포함한 보고치이며 최종 글의 길이나 청구 금액과 다릅니다.
동시 실행과 제공자 캐시 때문에 속도의 인과적 개선으로 해석할 수 없습니다.
글자 수를 품질 점수로 쓰지도 않습니다. 다른 모델에서 결함이 발견돼 0.2.0은 채택하지 않았습니다.

## 관측한 결함에 따른 수정

0.2.1은 실행 단계에 조건을 배치하고, 인계문의 반복을 줄이며, 편집을 한 번으로
제한하고, 백분위 변화의 확대 해석을 막도록 보완했습니다. [별도 프로토콜](repair-protocol.json)로
여덟 개를 확인했습니다. 일곱 개는 의미를 보존했지만 Grok의 새 성능 보고 표에서
B의 성공 칸에 A의 오류 제외 조건이 들어갔습니다. 본문은 B 1,000건으로 맞았습니다.
서로 모순되므로 전체 통과 조건을 만족하지 못했고 설치하지 않았습니다.
[판정](repair-author-grades.json)과 [실행 기록](repair-results.json)을 보존했습니다.

[0.2.2](final-candidate/ko-technical-writing/README.ko.md)는 숫자 표의 열별 원자료 대조와
본문과의 일치를 확인합니다. [최종 프로토콜](final-protocol.json)은 전체 파일을 고정하고
별도 최대 10회로 표적 회귀 검사를 반복합니다. `final_round.py generate`·`smoke`로 실행하고
`final_summary.py`로 집계합니다. 결함을 본 뒤 반복한 회귀 검사이며 새 독립 비교가 아닙니다.
0.2.0의 점수를 최종 버전의 점수로 옮겨 쓰지 않습니다.

## 최종 개인용 설치

**0.2.2**를 `~/.codex/skills/ko-technical-writing`에 설치했습니다.
[설치 근거](installation.json)에서 여섯 파일이 최종 후보와 일치하고, 설치본을 실제로
읽어 작성한 실행도 통과했음을 확인할 수 있습니다. 교체 전 0.1.0의 변경 여부를 확인했고
Git 밖에 백업했습니다. 저장소 지원 제품·전역 정책·Claude/Cursor 설치는 추가하지 않았습니다.

[최종 결과](final-results.json)는 10회 시도 중 9개 답변 완료입니다. 세 모델의 회귀 초안
여섯 개, Opus 백분위 오류 재현, 실제 JSON 작성, 설치본 실행이 [작성자 검사](final-author-grades.json)를
통과했습니다. Grok 복귀 절차 첫 시도는 240초에 중단됐고, 같은 입력을 480초 제한으로
재시도해 151.952초에 완료했습니다. 첫 타임아웃도 분모에 남깁니다.
[재시도 기록](final-followup.json)에는 모델 호출 전에 멈춘 실행기 검증 오류도 남겼습니다.
최종 조건 문장에 남은 이전 버전 번호는 이미 고정된 0.2.2 파일 목록에 맞게
[바로잡았으며](final-protocol-erratum.json), 기준이나 통과 문턱은 바꾸지 않았습니다.

표적 회귀 검사에 따른 개인용 Codex 채택입니다. 0.2.2의 새로운 블라인드 비교나 사람의
이해도 실험은 아니며, 모든 요청에서 자연스러운 글을 보장하지 않습니다. Grok은 여전히
느리고 어색한 표현을 쓸 수 있어 지원 호스트로 추가하지 않았습니다. Opus/Grok은 지침을
입력에 넣어 평가했고 Codex는 실제 스킬 파일을 읽었습니다. 평소 스킬을 사용할 때
추가 모델을 호출하지는 않습니다.

## 서로 다른 제공자의 평가와 전체 실행 수

[추가 결과](external-results.json)는 39회 시도 중 37개 답변입니다. Claude CLI
2.1.292는 실제 `claude-opus-5-5`를 보고했습니다. high 추론을 요청했지만 실행 기록에는
추론 수준이 없었습니다. Cursor Agent 2026.10.01-e373342는 Grok 4.7 256K Medium을
보고했습니다. 그 전에 시도한 High 작성 한 건과 별도 Grok 평가 한 건은 시간 제한에 걸렸습니다.

| 작성 모델: 0.2.0과 일반 실행 비교 | 후보 선호 | 일반 실행 선호 | 동률 | 평가 미완료 |
|---|---:|---:|---:|---:|
| Opus 작성, Grok Medium 평가 | 4 | 1 | 0 | 1 |
| Grok Medium 작성, Opus 평가 | 5 | 1 | 0 | 0 |

같은 과제 여섯 개에서 버전을 숨긴 모델 선호입니다. A/B 위치는 균형 있게 배치했지만
순서를 바꾼 반복 평가는 없었습니다. 사람의 투표나 최종 버전의 점수가 아닙니다.
평가의 오류 지적도 모두 확정 결함은 아닙니다. 예를 들어 이미 전제 조건을 충족했고
재개 명령도 제공된 백필을 다음 행동으로 제시한 것을 근거 없는 지시라고 지적했습니다.
반대로 작성자는 높은 점수와 별개로 백분위 해석과 절차의 탐색 부담을 발견했습니다.
두 평가 모델 모두 의도적으로 넣은 202 완료 오류를 찾았고, 심한 반복은 군더더기 항목에
1점을 줬습니다. 뚜렷한 결함을 구분했다는 뜻이며 미묘한 문체 판별 능력까지 입증하지는 않습니다.

| Opus | 17589 | 14256 | 34.2345 | 47.7535 |
