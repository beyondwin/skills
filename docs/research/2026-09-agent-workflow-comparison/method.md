# 조사 방법

## 무엇을 알고 싶었나

superpowers를 쓰고 있을 때 dryforge나 다른 워크플로 도구로 바꿀 이유가 있는지
알고 싶었습니다. README 주장만으로는 판단하기 어려워서, 같은 과제를 같은 조건으로
끝까지 돌려 보고 결과를 비교했습니다.

## 1단계: 정적 분석

- 각 저장소를 `git clone --depth 1`로 받아 README와 모든 스킬·명령 파일을 읽었습니다.
  커밋과 날짜는 [도구별 특징](tools.md)에 있습니다.
- 도구 6개(mattpocock, gstack, BMAD, Spec Kit, OpenSpec, Ralph)는 서브에이전트가
  하나씩 맡았습니다. 각 에이전트는 저장소 분석, 격리 설치 스크립트 작성, haiku 모델로
  설치 확인(스킬 목록이 보이는지) 한 번까지 했습니다.
- superpowers는 이 PC에 설치된 6.4.1을 그대로 썼습니다.

## 2단계: 실측(probe)

### 조건 10개

기본 Claude Code(대조군), superpowers, dryforge, workflow-orchestrator, mattpocock,
gstack, BMAD, Spec Kit, OpenSpec, Ralph입니다. 조건 정의는
[`harness/conditions.json`](harness/conditions.json)에 있습니다.

### 격리

모든 세션은 Claude Code 2.1.280 `claude -p`로 돌렸습니다.

- 모델: `opus`(Claude Opus 5.5). 사용자가 평소 쓰는 모델과 같습니다.
- `--setting-sources project`: 사용자 설정, `~/.claude/skills`, 전역 훅을 읽지 않습니다.
  superpowers 세션 시작 훅도 superpowers 조건에서만 들어갑니다.
- `--plugin-dir`: 해당 조건의 플러그인만 올립니다. 프로젝트에 설치하는 도구(BMAD,
  Spec Kit, OpenSpec, gstack, Ralph)는 과제 저장소 안에 설치하고 "install" 커밋으로
  남긴 뒤 시작했습니다.
- `--strict-mcp-config`: claude.ai 계정 커넥터가 섞이지 않게 막았습니다. 파일럿에서
  이 옵션 없이 돌렸더니 커넥터 인증 안내가 답변에 섞였습니다.
- `--disallowedTools AskUserQuestion`: `-p` 모드에는 선택 UI가 없습니다. 모든 조건이
  질문을 평문으로 하도록 똑같이 막았습니다.
- `--permission-mode bypassPermissions`: scratch 디렉터리의 임시 저장소에서만 썼습니다.
- 확인: 조건마다 "사용 가능한 스킬을 나열하라"를 haiku로 돌려 해당 도구의 스킬만
  보이는 것을 확인했습니다.

### 과제 3개

| ID | 저장소 | 첫 요청 | 무엇을 보나 |
| --- | --- | --- | --- |
| S1 | 빈 저장소 | "가계부 CLI 하나 만들어줘" | 한 줄 요청에서 숨은 요구 9개를 얼마나 알아내나 |
| S2 | 쿠폰·배송비 계산 모듈(테스트 5개) | "쿠폰 두 장까지 같이 쓸 수 있게 해줘" | 문서(할인 상한 30%)와 코드(50%)의 충돌을 잡아 묻나. 조합·순서 규칙을 묻나 |
| S3 | 같은 모듈, `>=` 대신 `>` 버그 | "딱 50,000원 주문에 배송비가 붙었대. 고쳐줘" | 작은 수정에 드는 절차와 비용, 회귀 테스트 |

과제 저장소는 [`harness/fixtures/`](harness/fixtures/)에 있습니다.

### 모의 사용자

사람이 30번 대화할 수 없어서, 별도 모델(Sonnet)이 사용자를 연기했습니다.

- 과제마다 사용자만 아는 사실 시트가 있습니다([`harness/personas/`](harness/personas/)).
  예: S2의 "정률 1장 + 정액 1장만", "정률 먼저", "상한은 문서의 30%가 맞음".
- 규칙: 물은 것에만 답합니다. 묻지 않은 사실은 먼저 말하지 않습니다. 단, 승인하라고
  보여 준 설계가 사실과 명백히 다르면 실제 사용자처럼 바로잡습니다. 이것을
  "사용자가 바로잡음(correction)"으로 따로 기록했습니다.
- 도구마다 문서에 적힌 사용 순서(playbook)를 받았습니다. 예: dryforge는 의도 문서를
  승인할 때 `/dryforge:go`를 입력합니다. Spec Kit은 `specify → clarify → plan → tasks →
  implement → converge`를 차례로 입력합니다.
- git 규칙도 사실 시트에 있습니다. S2는 "로컬 브랜치에 커밋만, 머지·push·PR 금지"입니다.
- 모의 사용자는 저장소 파일을 읽을 수 있습니다(Read, Grep, Glob). 스펙 문서를 보고
  승인하기 위해서입니다.

### 끝까지 진행

[`harness/driver.py`](harness/driver.py)가 첫 메시지를 보내고, 에이전트 답을 모의
사용자에게 넘기고, 그 답을 `--resume`으로 이어 보냅니다. 모의 사용자가 "끝"이라고
판단하거나 14턴이 되면 멈춥니다. 14턴 상한에 걸린 것은 gstack뿐이어서, gstack 격리
재실행은 상한을 30턴으로 두었습니다(`PROBE_MAX_TURNS=30`). 처음 실행은 같은 세션으로
16턴을 더 이어 돌렸습니다([`harness/continue_gstack.sh`](harness/continue_gstack.sh)). Ralph는 요구사항 대화가 끝나면 문서대로 계획 루프
2회와 구현 루프(S1 8회, S2 6회, S3 4회 상한)를 사람 없이 돌렸습니다.

### 채점

[`harness/judge.py`](harness/judge.py)가 두 가지로 채점했습니다.

1. 숨긴 결정적 검사: 결과 코드를 직접 import해 확인합니다. S2는 "50% 쿠폰 1장이
   30%에서 잘리나", "기존 1장 호출이 그대로 되나", "무료배송 50,000원", "문서의
   '주문당 1장만' 규칙이 갱신됐나"를 봅니다. S3는 경계값과 회귀 테스트 추가를 봅니다.
   결과가 브랜치에 커밋돼 있으면 그 커밋을 꺼내 검사합니다.
2. 독립 채점자: 대화에 참여하지 않은 Opus 세션이 저장소 복사본에서 코드를 직접
   돌려 보고 루브릭으로 채점합니다. 사실마다 "물어서 얻음 / 문서·코드로 확인 /
   묻지 않고 맞게 가정 / 틀리게 가정 / 빠짐"으로 분류하고, 불필요한 질문 수, 검증
   주장이 사실인지, git 규칙 준수를 봅니다.

### 파일럿에서 고친 것

- claude.ai 커넥터가 섞이던 문제 → `--strict-mcp-config` 추가. 파일럿 결과는 버렸습니다.
- 숨긴 검사 두 개의 오류: "1장만" 문자열 검사가 새 규칙 문장("정률 1장 + 정액 1장만
  허용")에도 걸렸습니다. 또 결과가 다른 브랜치에 커밋된 경우를 보지 못했습니다.
  둘 다 고친 뒤 모든 실행에 다시 적용했습니다.
- `src/` 구조 프로젝트는 `PYTHONPATH=src`가 있어야 테스트가 돕니다. 숨긴 테스트
  검사가 이를 실패로 보던 것을 고쳤습니다.
- 비용: `claude -p --resume`은 `total_cost_usd`를 세션 누적값으로 보고합니다. haiku로
  3턴 대조 실험을 해서 확인했습니다(0.0157 → 0.0182 → 0.0207). 처음에는 턴마다
  더해 부풀려 집계했습니다. 지금은 세션의 마지막 값을 쓰고, Ralph처럼 매번 새
  세션인 루프만 더합니다.

## 이 조사가 증명하지 못하는 것

- 조건×과제마다 1회씩만 돌렸습니다. 모델 출력은 매번 다르므로, 한 번의 차이를
  도구의 확정적 성질로 읽으면 안 됩니다. 반복해서 나타난 패턴만 결론에 썼습니다.
- 모의 사용자는 진짜 사람이 아닙니다. 가끔 사용 순서를 벗어났습니다(예: mattpocock
  S2에서 `/to-spec` 대신 "나머지도 진행해줘"라고 답해 곧바로 구현됨). 이런 경우는
  결과표에 적었습니다.
- 비용은 Claude Code가 보고한 `total_cost_usd`(API 단가 환산, 캐시 포함)입니다.
  구독 사용량과 다를 수 있습니다. 모의 사용자와 채점자 비용은 빼고 따로 적었습니다.
- gstack은 설치된 Codex CLI를 외부 의견으로 불렀습니다. 그 비용과 영향은 측정에 없습니다.
- gstack은 과제 저장소 밖의 상태 폴더에 기록을 남깁니다. 처음 실행은 이 폴더를 과제끼리
  같이 써서 기록이 섞였습니다. 실행 폴더마다 `GSTACK_HOME`을 따로 두도록 하네스를 고치고
  S1~S3를 한 번에 하나씩 다시 돌렸습니다. 표의 gstack 행은 재실행 값입니다.
- 과제가 작습니다(파이썬 모듈 1개, CLI 1개). 큰 저장소, 여러 날 걸리는 일, 팀
  협업에서의 차이는 재지 않았습니다.
- 채점자도 Claude 모델입니다. 숨긴 결정적 검사로 일부를 보완했습니다.
