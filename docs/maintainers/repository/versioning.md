# 버저닝

제품 버전의 원본은 `skills/<name>/release.toml`입니다. `SKILL.md`의 `metadata.version`은 Agent Skills 소비자가 읽는 배포용 복제 값이며, CI가 두 값을 함께 바꾸도록 강제합니다. 도구가 소스를 조용히 맞추지 않습니다.

카탈로그 버전의 원본은 `catalog/release.toml`입니다. 플러그인 매니페스트 버전은 이와 같아야 합니다. 카탈로그 숫자는 스킬 숫자와 맞출 필요가 없습니다.

개발 중 `release.toml.version`은 다음 출시 목표입니다. 설치 페이로드가 마지막 공개 제품 태그와 달라졌는데 버전이 그대로면 검사가 실패합니다. 릴리스 준비 시 `Unreleased` 항목을 `## <version> - <date>`로 확정하고 새 빈 `Unreleased` 섹션을 엽니다.

## 스킬 SemVer

SemVer는 파일 수가 아니라 외부에서 관찰 가능한 제품 계약의 영향을 기준으로 판단합니다.

| 변경 | 스킬 버전 | 예시 |
| --- | --- | --- |
| 문서화된 계약을 회복하는 호환 결함 수정 | PATCH | 잘못된 분기, 깨진 상대 링크, 투명한 보안 강화 |
| 설치되는 README·CHANGELOG·패키지 메타데이터 변경 | PATCH | 설치법 정정, 릴리스 provenance 보강 |
| 기본 동작을 유지하는 명시적 opt-in 기능 | MINOR | 새 선택 모드, 새 선택 인자, 선택적 스크립트 |
| 활성화 또는 near-miss 경계의 비호환 변경 | MAJOR | 이전에 no-op이던 요청의 암묵 활성화 |
| 기본 모드·기본 출력·필수 입력 변경 | MAJOR | 기본 경로 변경, 출력 형식 제거 또는 이름 변경 |
| 필수 런타임·안전·데이터 처리 계약 변경 | MAJOR | 새 필수 공급자, 데이터 보존 정책 변경 |
| 설치되지 않는 테스트·관리자 문서·CI만 변경 | 없음 | 테스트 리팩터링, 내부 운영 문구 정리 |

`SKILL.md`, `agents/openai.yaml`, 런타임 `references/`와 `scripts/` 변경은 단순 문구 수정으로 자동 간주하지 않습니다. 에이전트 동작에 영향을 줄 수 있으므로 계약 영향 평가와 최소 PATCH가 필요합니다. 반대로 관리자 문서나 저장소 검증 도구만 바뀌고 배포 제품이 동일하면 스킬 버전을 올리지 않습니다.

## 카탈로그 SemVer

카탈로그 SemVer는 번들을 설치하는 사용자의 호환성 영향을 따릅니다.

- 채택한 스킬 중 MAJOR가 있으면 카탈로그 MAJOR
- 채택한 스킬 중 가장 높은 변경이 MINOR면 카탈로그 MINOR
- PATCH만 채택하면 카탈로그 PATCH
- 새 스킬 추가는 MINOR, 스킬 제거·이름 변경은 MAJOR
- 카탈로그 표시 문구나 호환 결함 수정은 PATCH

개별 스킬 릴리스가 카탈로그 lock이나 카탈로그 버전을 자동으로 바꾸지 않습니다. 채택은 [카탈로그](catalog.md)의 별도 작업입니다.

## 태그

- 제품 태그: `<name>-v<version>` annotated tag. 이미 있는 태그는 재사용하거나 이동하지 않습니다.
- 카탈로그 태그: `beyondwin-skills-v<version>`
- 기존 통합 태그 `v2.0.0`은 레거시 기준선으로 보존합니다. 소급해 제품 태그를 만들지 않습니다.
